# Сценарии расследования ошибок

Используйте эти сценарии для ошибки, регрессии, нестабильного падения,
инцидента или ошибки безопасности. Советник может предложить профиль
расследования ошибок по тексту задачи, но проверка рабочего цикла остаётся
выключенной, пока проверенный зафиксированный план явно не включит её.

## Начало через приём задачи

```bash
cat > work/bugs/checkout-regression.md <<'EOF'
# Задача

Найти и исправить регрессию в расчёте заказа.

Известная падающая проверка:
pytest tests/checkout/test_totals.py::test_discount_total

Ожидаемый результат:
- воспроизвести падение до правки;
- определить стабильный отпечаток ошибки;
- вести принятые и отвергнутые гипотезы;
- доказать, что тот же отпечаток стал зелёным после правки;
- зафиксировать отсутствие побочного ущерба.
EOF

agent-lifecycle adapter task start \
  --adapter codex \
  --file work/bugs/checkout-regression.md \
  --out work/bugs/checkout-intake.json
```

В подтверждении может появиться `bugForensicsAdvisory.recommendation: SUGGEST`
и `recommendedQualityProfiles: ["bug-forensics"]`. Это только рекомендация. Она
не включает проверку рабочего цикла и не запускает реализацию.

## Поиск ошибки

Используйте этот путь, когда ошибка видна, но причина ещё не локализована.

```bash
agent-lifecycle adapter task start \
  --adapter codex \
  --text "Исследуй падающую проверку расчёта заказа. Код не менять, пока падение не воспроизведено." \
  --out work/bugs/defect-search-intake.json
```

План должен требовать:

- `agent-bug-reproduction-receipt.v1` до правок кода;
- `agent-failure-fingerprint.v1` со стабильными признаками ошибки;
- `agent-bug-hypothesis-ledger.v1` с отвергнутыми альтернативами;
- `agent-regression-proof-receipt.v1` для подтверждения красного и зелёного
  состояния;
- `agent-fix-impact-receipt.v1` для влияния правки и соседних проверок.

## Исправление регрессии

Используйте этот путь, когда поведение раньше работало, а теперь падает.

```bash
agent-lifecycle report change-summary \
  --project-root . \
  --base origin/main \
  --out work/bugs/regression-change-summary.json
```

В плане привяжите падающую команду, отпечаток ошибки и подозреваемый диапазон
изменений. Правка принимается только если тот же отпечаток красный до изменения
и зелёный после изменения.

## Нестабильные падения

Используйте этот путь, когда проверка иногда проходит, а иногда падает.

```bash
cat > work/bugs/flaky-task.md <<'EOF'
# Задача

Исследовать нестабильную проверку повторной оплаты.

Подтверждения:
- количество повторных запусков;
- количество падений;
- был ли успешный повтор;
- стабильный отпечаток ошибки, если он есть.
EOF
```

Сигналы нестабильности можно приложить к артефакту проверки, но они не заменяют
воспроизведение, отпечаток, журнал гипотез, регрессионное подтверждение или
подтверждение влияния правки.

## Ошибка безопасности

В переносимых документах используйте только синтетический текст задачи и
очищенные подтверждения. Не вставляйте реальные секреты, вредоносные строки или
частные детали инцидента в файлы задач.

```bash
agent-lifecycle adapter task start \
  --adapter codex \
  --text "Исследуй ошибку безопасности в проверке запроса, используя только очищенные подтверждения." \
  --out work/bugs/security-intake.json
```

Для задач S2 или задач с риском безопасности проверка профиля требует
подтверждение перепроверки, если ошибка классифицирована как `security-bug` или
`race`.

## Граница

- Рекомендация сама по себе никогда не включает обязательные проверки.
- Чтобы проверка активировалась, в проверенной задаче или зафиксированном плане
  должно быть `qualityProfile: bug-forensics`, `qualityProfiles:
  ["bug-forensics"]` или `bugForensics.enabled: true`.
- Профиль использует существующие артефакты и не вводит дублирующие схемы
  базового подтверждения, отпечатка ошибки или регрессионного подтверждения.
