# Проверка внешней рабочей оболочки модели

[Английская версия](https://github.com/avksp/agent-lifecycle-kit/blob/main/docs/guides/model-harness-evaluation.md)

Используйте это руководство, когда модель или рабочая оболочка запускается вне
ALK, а сравнение качества и ресурсов должно быть повторяемым. Внешняя оболочка
выполняет задачу и создаёт запись выполнения без чувствительных данных со схемой
`agent-benchmark-run-receipt.v1`; ALK проверяет и сравнивает эти записи.

Вариант выполнения — это нейтральное сочетание адаптера, класса модели, среды
и оценщика для одного набора задач. В имени схемы техническое слово `receipt`
сохранено ради совместимости.

1. Создайте воспроизводимую выборку командой `agent-lifecycle benchmark sample`.
2. Выполните один и тот же набор задач каждым вариантом выполнения.
3. Запишите в каждую запись выполнения отпечатки задачи, среды и оценщика.
4. Проверьте каждую запись командой `agent-lifecycle benchmark receipt-check`.
5. Проверьте каждый вариант командой `agent-lifecycle benchmark qualify`.
6. Сравнивайте только варианты с техническим статусом `QUALIFIED` командой
   `agent-lifecycle benchmark compare-routes`.

Подтверждение качества обязательно до вывода о токенах или времени. Минимум
составляет пять задач, два завершённых запуска каждой задачи, пять групп
`family/tier/shape` и два запуска каждой группы. Недостающие данные о качестве
или смешанное происхождение измерений дают `NO_RECOMMENDATION` или
`INCOMPARABLE`.

Внешняя оболочка может использовать облачную, малую или локальную модель. Она
отвечает за выбор модели и запуск процесса; ALK не вызывает провайдера, не
запускает хост и не выбирает вариант выполнения автоматически.
