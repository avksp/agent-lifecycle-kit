# Архив закрытого локального пакета плана

Команда `project archive` копирует закрытый пакет в приватный ZIP вне
рабочего дерева Git. Приостановите изменения в проекте на время копирования.

Подготовьте каталог пакетов и их предшественников в пределах вашего проекта.
Включите активные пакеты. Они могут ссылаться на закрытые. Передайте точный
SHA-256 байтов каталога.

```json
{
  "schemaVersion": "agent-local-package-catalogue.v1",
  "scope": "my-project",
  "complete": true,
  "packages": [{
    "id": "sample",
    "manifest": "tasks/sample/plan.manifest.json",
    "predecessorIds": [],
    "state": "work/sample/run.state.json",
    "proof": "work/sample/final-proof.json"
  }]
}
```

Указывайте входные пути относительно корня репозитория. Для пакета без
запуска опустите `state` и `proof`. Для запущенного пакета без финального
доказательства опустите `proof`. Отмечайте каталог полным, когда в нём есть
все пакеты и связи с предшественниками в выбранной области. ALK проверяет
предоставленную область.

```sh
agent-lifecycle project archive inventory --catalogue work/catalogue.json --catalogue-sha256 SHA
agent-lifecycle project archive create --catalogue work/catalogue.json --catalogue-sha256 SHA \
  --inventory-digest DIGEST --package sample --out /private/archives/sample.zip
```

Укажите новое имя ZIP в существующей папке, которой вы управляете. Путь
должен быть вне корня проекта, его предков и потомков. Для копирования
нужны связанное доказательство COMPLETE и обычные файлы, игнорируемые Git
и отсутствующие в индексе. Корни плана и работы должны быть раздельными.
Крупный закрытый пакет может превысить предел в 1024 элемента, 8 МиБ на
файл или 64 МиБ суммарно.

В `archive-manifest.json` внутри ZIP сверяйте пути, размеры и SHA-256.
Исходные файлы сохраняются. Удаление исходников требует отдельного решения
оператора. После ошибки записи проверьте целевую папку и выберите новое
имя для повтора.
