# Рабочие сценарии проверки кода

ALK проверяет не только строки изменений, но и соответствие задачи,
архитектуры, подтверждений и границ выпуска.

## Проверка переданной реализации

Если один человек подготовил план и реализовал его, а другой принимает работу,
передайте папку плана и артефакты рабочего цикла. Проверяющий запускает:

```bash
agent-lifecycle audit package \
  --plan-dir tasks/release-1-63 \
  --state work/release-1-63/run.state.json \
  --base main \
  --require-frozen \
  --require-implementation \
  --strict \
  --out work/release-1-63/evidence/package-audit.json
```

Команда проверяет полноту плана, таблицу критериев приёмки, lock, ссылки на
репозитории, соответствие состояния плану, принятые отчёты аудита задач и
владение изменёнными файлами. Результат `PASS` означает, что передача прошла
проверку. При `FAIL` или `REVIEW_REQUIRED` отчёт содержит конкретные причины.

Если список отчётов нужно задать вручную, передайте каждый путь отдельным
параметром `--report`. Для предварительной проверки папки плана используйте
`agent-lifecycle audit package --plan-dir <папка>` без `--state`.

Подробное описание форматов и отдельных проверок находится в
[`Сводной проверке реализации`](../reference/implementation-audit.md).
