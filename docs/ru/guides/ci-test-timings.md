# Измерения длительности тестов CI

Workflow `ci` сохраняет артефакт `test-timings-<os>-py<version>` на 14 дней
для каждого начатого полного stdlib-прогона, включая неуспешный. Матрица ОС и
Python, отдельный security-прогон и последующие валидаторы сохранены. Это
инфраструктурное изменение без новой версии приложения ALK.

Локальное воспроизведение:

```sh
uv run --frozen --group quality python tools/ci/run_unittest.py \
  --start tests --top . --out work/ci/local-test-timings.json
```

Для каждого запуска нужен новый путь отчёта. Существующий отчёт, ошибка записи,
ошибка discovery/импорта, неполный запуск или отрицательный результат unittest
дают ненулевой exit code. RUNNING и FAIL — диагностические данные, не PASS.

Используется штатный `TestLoader.discover` и исходная вложенная suite без
перестройки. Последовательность, повторяющиеся test IDs, фикстуры, ошибки,
пропуски, expected failure и unexpected success сохраняются. Монотонное время
теста включает setup, тело, teardown и cleanup. Фикстуры класса/модуля и discovery
входят в `wallSeconds` и `unassignedSeconds`, а не приписываются отдельному методу.
`suiteSeconds` исключает discovery. Пропуск общей фикстуры явно объясняет
обнаруженные, но не начатые тесты; ошибка фикстуры остаётся ошибкой. События subtest
ссылаются на конкретный запуск родительского теста. Отсутствующее время не равно
нулю. Аварийное завершение процесса может оставить только отчёт RUNNING.

Отчёт содержит обнаруженный список, начатые тесты, события, итоговые счётчики,
Python/платформу и доступные идентификаторы GitHub-запуска. Текстовые сообщения
unittest сохраняются. Модельные вызовы и секреты не добавляются.

Windows использует `tools/ci/run_parallel_unittest.py`; Linux и macOS сохраняют
последовательный runner. Координатор обнаруживает полную исходную suite и
выделяет ровно одно целое поддерево корневой suite с модулем
`tests.workflow.test_limited_usage`. Оно и остальные исходные поддеревья
выполняются двумя процессами внутри прежнего matrix-задания. Вложенность,
фикстуры класса/модуля, порядок внутри группы и повторяющиеся IDs сохраняются.
Разделение, которое склеивает границы фикстур одного модуля, запрещено.
Если безопасное разделение не подтверждено, уже обнаруженная полная suite
выполняется один раз последовательно до старта исполнителей; отчёт содержит
`mode: serial`.

Исполнители получают отдельные временные Git-копии точного committed HEAD
с `--no-hardlinks`, собственные scratch-каталоги и восстановленную версионную
фикстуру в каждой копии. Изменённые tracked-файлы и неигнорируемые untracked-файлы
запрещают старт. Перед тестами проверяются detached HEAD, полный упорядоченный
список и назначенные исходные поддеревья. Координатор сверяет оба отчёта и
полное мультимножество IDs. Ошибка группы не отменяет обычное выполнение другой.
Отсутствующий, устаревший, частичный, противоречивый, прерванный или отрицательный
результат не может стать PASS. После старта исполнителей нет автоматического
повтора или последовательного обхода ошибки. Используется существующее
ограниченное владение деревом процессов; ошибка владения или очистки остаётся
отказом. Git-копии изолируют состояние тестовых репозиториев; полной изоляции ОС
и внешних сервисов они не предоставляют.

Windows-артефакт содержит общий отчёт, `test-timings/<worker>/roster.json`,
отчёты исполнителей и полные stdout/stderr, в том числе при отказе.
`alk-ci-test-timings.parallel.v1` разделяет `parallelWallSeconds`,
`summedWorkerWallSeconds`, `summedCaseSeconds`, подготовку, окно работы
исполнителей и проверку/очистку. Суммарное время одновременно исполнявшихся
тестов не вычитается из wall time как последовательные накладные расходы.
Отчёты исполнителей сохраняют исходную схему. Внутренний `--worker-roster`
самостоятельно не доказывает полноту suite; обычный последовательный режим
не меняется. Поля wall исключают финальную сериализацию JSON; время тестового
шага GitHub включает весь старт команды, копирование, discovery, запись логов
и отчётов.

Отдельный `ci-timing-control` выполняет оба полных режима в одном задании
Windows/Python3.11 на одном checkout SHA. Порядок фиксирован заранее: сначала
параллельный, затем последовательный. Прогрев кэшей тем самым помогает
последовательному контролю, а не новому режиму. Общие runner, образ и интерпретатор
позволяют сравнивать времена двух тестовых шагов GitHub. В разных заданиях версии
образа могут различаться даже при одинаковых SHA и метке runner; такое сравнение
не подтверждает допуск. Несопоставимый образец сохраняется. Ручной запуск возможен
только для отдельно разрешённого сравнения. До включения обязательны все прежние проверки
ОС/Python3.11–3.14, успешный контроль, одинаковые списки/исходы/пропуски тестов,
сопоставимые доступные сведения о среде и сокращение wall time тестового шага
GitHub минимум на **15%**. Все исходные и отрицательные образцы сохраняются;
повторы ради удачного времени запрещены. Одна пара доказывает наблюдённый
результат, а не median, p95 или будущую гарантию. Очередь, wall time задания
и суммарные runner-minutes учитываются отдельно. Доказательства сравнения —
в [инфраструктурном PR](https://github.com/avksp/agent-lifecycle-kit/pull/189).
Сам факт реализации ещё не доказывает ускорение. Кэш фикстур, новая версия
приложения и смена зависимостей сюда не входят. При отрицательном допуске
Windows возвращается к `run_unittest.py`, данные проверки сохраняются.

Основа: [контракт Python unittest](https://docs.python.org/3.11/library/unittest.html#unittest.TextTestRunner)
и [actions/upload-artifact](https://github.com/actions/upload-artifact).
