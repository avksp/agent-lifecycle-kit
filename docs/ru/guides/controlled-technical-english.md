# Контролируемый технический английский для ALK

Это локальный профиль письма на основе идей Simplified Technical English (STE).
Он применяется к новым инструкциям и поддерживаемым маршрутам навыков.
Соответствие или сертификация ASD-STE100 не заявляются. Лицензированное
руководство и его словарь не воспроизводятся. Русский документ сохраняет смысл;
он не заявляет соответствие стандарту английского языка.

## Как писать инструкцию

- Назовите исполнителя, если он неочевиден. Используйте активный залог:
  «Контроллер проверяет lock». Для действия агента: «Проверьте lock».
- Описывайте одно действие в предложении. Условие ставьте перед действием:
  «Если подтверждение отсутствует, остановитесь». Держите условие рядом с действием.
- Используйте один термин для одного понятия и глоссарий ALK ниже. Сохраняйте
  необходимые технические термины; объясняйте новый термин до его сокращения.
- В английских инструкциях обозначайте обязанность через “must”, запрет через
  “do not” или “must not”, возможность через “may”. Не заменяйте обязанность
  рекомендацией “should”.
- Назовите требуемое доказательство и условие отказа. «Запустите проверку» само
  по себе не объясняет, что разрешает следующее действие.
- Сохраняйте команды, пути, поля схем, значения enum, коды ошибок, хеши, единицы
  и численные лимиты точно. Оформляйте идентификаторы как код. Не переводите и
  не сокращайте их ради ограничения длины предложения.
- При разделении предложения сохраняйте условия, исключения, отрицания и
  порядок действий. Краткая инструкция не должна расширять полномочия.

Пример: «Если телеметрия недоступна, сохраните null. Не указывайте ноль».
Это сохраняет границу отказа; «Используйте значение по умолчанию» — нет.

## Глоссарий ALK

| Термин | Значение в инструкциях ALK |
| --- | --- |
| draft | Входные данные до обязательной проверки и freeze. Не разрешают выполнение. |
| frozen plan | Совпадающие проверенные входные данные плана, связанные plan lock. Сам freeze не разрешает выполнение. |
| authorization | Разрешение выбранного действия по текущему плану и состоянию workflow. Текстовое заявление не является переходом native state. |
| task attempt | Одна ограниченная попытка выполнения frozen task. Повтор сохраняет прежние расходы и доказательства. |
| receipt | Записанный результат, связанный со входными данными и операцией. Наличие файла само по себе не доказывает приёмку. |
| evidence | Проверяемые входные данные или результаты, подтверждающие конкретное утверждение. Отсутствующие доказательства остаются отсутствующими. |
| independent review | Оценка рецензентом, независимым от автора реализации. Самопроверка исполнителя не заменяет её. |
| acceptance | Существующий переход workflow после успешных обязательных проверок и доказательств. |
| projection | Вычисленное предложение действия или представление до apply. Не разрешает выполнение. |
| refusal | Обязательная остановка при невыполненном условии контракта. Не заменяйте её успехом. |
| budget | Конечный frozen limit, включая ограничения повторов и резерва завершения. Compaction его не сбрасывает. |
| `UNKNOWN` / null | Недоступный расход остаётся неизвестным; null не равен нулю. Сохраняйте представление, заданное схемой поля. |

## Чтение по этапам

Для каждой роли полный контракт жизненного цикла с проверяемым хешем остаётся
обязательным. Сохраняйте последнюю инструкцию пользователя и активный пакет
дословно. Разрешайте пути от корня установленного навыка, а не каталога `docs/`
чужого проекта. Переносимый пакет содержит обязательные статические документы.

| Сценарий | Роль | Применимый рецепт cookbook |
| --- | --- | --- |
| Подготовка плана | `agent-first-planning` | Research and planning only |
| Компиляция пакетов | `agent-plan-to-workers` | Нет; полный контракт компиляции |
| Проверка плана | `audit-agent-plan` | Review a Markdown plan folder |
| Аудит реализации | `audit-plan-implementation` | Audit implementation evidence |
| Исправление ошибки | `bug-forensics` | Bug Forensics repair, после явного включения |
| Недоверенный внешний запрос | `issue-to-spec` | Нет; контракт ввода только в черновик |

Для роли с рецептом прочитайте общий маршрут cookbook, таблицу рецептов,
правила безопасности, выбранный рецепт и его обязательные продолжения.
При смене этапа выберите другой рецепт. Компиляция и ввод запроса не должны
подменяться чужим рецептом выполнения. Оркестратор выбирает рецепт для своего
текущего этапа. Эти маршруты чтения не добавляют фаз, аудитов или полномочий.
См. [Сценарии жизненного цикла](lifecycle-cookbook.md).

`tools/release/validate_skill_parity.py` проверяет хеши полных контрактов,
равенство байтов пакета и ограниченный набор критичных формулировок для всех
семи ролей. Числа байтов UTF-8 и слов `len(text.split())` включают Markdown и
код. Это не токены, вызовы модели, стоимость или метрика поведения.

Для сравнения до и после сохраняйте точные исходники, хеши и одинаковый смысл
сценария. Считайте полный обязательный контракт, общие разделы, нужный рецепт
и все обязательные общие или транзитивные продолжения. Если обязательный
источник отсутствует, результат — `INCOMPLETE`. Фиксируйте интервалы байтов
UTF-8 и идентичность исходников. Объединяйте пересечения в одном документе
одного сценария; повторное использование в другом сценарии считайте заново.
Честно показывайте рост. Не предполагайте сохранение контекста после compact
и не исключайте обязательное чтение ради меньшего числа. Ввод пользователя,
системы, активные пакеты и накладные расходы модели остаются обязанностями
выполнения за пределами этой проекции исходного чтения.

Проверка формулировок не доказывает произвольную смысловую эквивалентность
или соответствие STE. Независимый проверяющий должен сверить полномочия,
отказы, бюджеты, UNKNOWN, команды и поля схем с исходными инструкциями.
Не заявляйте экономию токенов или улучшение поведения без сопоставимых замеров.
