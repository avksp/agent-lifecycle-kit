# Миграция исторических артефактов runner

В релизе 2.0 публичная поверхность контролируемого runner удалена. Старые
JSON-файлы состояния, переходов, снимков и восстановления остаются читаемыми
через один явный конвертер, чтобы хранить архив без второго владельца
полномочий выполнения.

## Преобразование одного артефакта

```bash
agent-lifecycle workflow migrate-runner-artifact \
  --input /path/to/legacy-runner-artifact.json \
  --output /path/to/legacy-conversion.json
```

По умолчанию вход ограничен 1 MiB. Конвертер проверяет поддерживаемую старую
схему и её самодайджест, где он определён, отклоняет симлинки и нестабильное
чтение и не заменяет существующий выходной файл. Приватная запись содержит
SHA-256 и размер источника, неперенесённые поля и стабильные блокеры.

## Правила полномочий

Преобразование read-only и неавторитетно. Оно всегда записывает
`authorityClaimed: false`, `stateWritten: false`, `modelCallsStarted: false` и
`hostLaunchStarted: false`. Конвертер не создаёт состояние workflow, не
возобновляет попытку, не меняет план, не вызывает модель, не запускает host и
не заявляет публикацию в production.

Для новой работы используйте текущее состояние workflow и замороженный план.
Conversion-запись не заменяет приёмку задачи, финальный аудит или гейты
публикации.

## Обработка отказов

Неизвестная схема, повреждённый или слишком глубокий JSON, устаревший дайджест,
слишком большой или изменившийся во время чтения вход, симлинк и уже занятый
выходной файл приводят к отказу с типизированной ошибкой. Исходный артефакт
нужно сохранить и исследовать ошибку до повторной конвертации.

Конвертер входит в совместимую поверхность 2.x. Его удаление является отдельным
решением для мажорной версии и не может произойти до 3.0.
