# Проверка цепочки запуска в CI

Запускайте `agent-lifecycle audit verify-chain` из доверенного пакета или
checkout. Репозиторий предоставляет доказательства. Владелец проверяющей
среды передаёт конфигурацию доверия и конечную отметку из отдельного
защищённого источника.

## Подготовьте входы

Подготовьте неизменяемую копию одного завершённого строгого запуска.
Сохраните пути относительно корня доказательств. Включите замороженный
манифест и lock, состояние и объекты по его ссылкам, журнал событий,
отчёты, подтверждения исполнения и обязательные файлы подписей. Первая
версия поддерживает один принятый строгий план и одно финальное решение.
При отсутствии записей о допуске ранних попыток результат — `NOT_CHECKED`.

Укажите манифест, lock, состояние, журнал и цепочку подтверждений в
`agent-chain-verification-bundle.v1`. Цепочка содержит SHA-256 исходных
байтов выбранных файлов. Включите файлы, на которые ссылаются запуск и
проверяемые подписи. Файлы самой цепочки и её входного описания исключите.

Закрепите в конфигурации канонический хеш политики ревьюеров. При наличии
операторской политики закрепите и её хеш. Конечная отметка связывает
идентификаторы запуска, пакета, плана и исходников, финальную ревизию и
хеши исходных байтов входного описания, lock, состояния, журнала, цепочки
и конфигурации. Владелец проверяющей среды подтверждает значения для
ожидаемого запуска и хранит конфигурацию и отметку вне корня доказательств.
Копирование хешей из непроверенного входа не подтверждает независимость.

Команда печатает один отчёт JSON и не пишет файлы. Код `0` означает
успешную проверку выбранных данных. Код `1` указывает на несоответствие
доказательств или неподдерживаемую проверку. Код `2` означает неверный
селектор входа либо недоступный входной аргумент. Отключённые подписи
оператора отмечены как `NOT_APPLICABLE`. Успех подтверждает выбранные
открытые входы. Хранение ключей и изоляция среды требуют отдельного
доказательства развёртывания.

## Настройте задание

Используйте workflow, определение и обязательный статус которого нельзя
изменить из недоверенного PR. Замените репозиторий и полный SHA в примере
на защищённый репозиторий и проверенный коммит владельца. Храните там
wheel, конфигурацию доверия и конечную отметку. Checkout PR служит только
входом проверки. [Рекомендации GitHub по безопасности](https://docs.github.com/en/actions/reference/security/secure-use)

```yaml
name: Verify selected run
on: pull_request
permissions:
  contents: read
jobs:
  verify-run:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1
        with:
          path: evidence
          persist-credentials: false
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1
        with:
          repository: OWNER/protected-verifier-inputs
          ref: REPLACE_WITH_FULL_REVIEWED_COMMIT_SHA
          path: verifier
          persist-credentials: false
      - uses: actions/setup-python@6d4fd22b20465ccc0f7354476588e8df7c9ca0e0
        with:
          python-version: "3.12"
      - run: |
          python -m venv "$RUNNER_TEMP/chain-verify"
          "$RUNNER_TEMP/chain-verify/bin/pip" install --no-index --no-deps \
            "$GITHUB_WORKSPACE/verifier/agent_lifecycle_kit-2.51.0-py3-none-any.whl"
          "$RUNNER_TEMP/chain-verify/bin/agent-lifecycle" audit verify-chain \
            --repository-root "$GITHUB_WORKSPACE/evidence" \
            --bundle receipts/bundle.json \
            --trust-config "$GITHUB_WORKSPACE/verifier/trust.json" \
            --anchor "$GITHUB_WORKSPACE/verifier/anchor.json"
```

Сохраните checkout доказательств доступным только для чтения на время
проверки. Не передавайте процессу учётные данные моделей, секреты окружения
или право записи в доказательства. Проверяющая команда не использует сеть.
Checkout и настройка окружения выполняются заранее. Владелец сначала
подтверждает доверенные входы и ожидаемый результат. Затем добавляет
защищённый workflow или обязательную проверку в настройках репозитория.
Сам пример настройки репозитория не меняет.

См. [происхождение доказательств ревьюера](../reference/audit-evidence-and-reviewer-provenance.md)
и [справочник CLI](../reference/cli.md).
