# Рабочие процессы для начинающих и продвинутых пользователей

[English version](https://github.com/avksp/agent-lifecycle-kit/blob/main/docs/guides/beginner-and-advanced-workflows.md)

Для обычной задачи ALK предлагает одну простую точку входа, а для точного
контроля — отдельные команды жизненного цикла. Оба варианта используют одни и
те же правила плана, подтверждений и приёмки.

## Для начинающих

1. Установите ALK по руководству [установка ALK и первый запуск](install-and-first-run.md).
2. Посмотрите доступные маршруты:

   ```bash
   agent-lifecycle project preset list
   ```

3. Передайте задачу из файла или текста. Выберите адаптер, установленный на
   компьютере:

   ```bash
   agent-lifecycle start --adapter <идентификатор> --preset research-review --file task.md
   ```

   или:

   ```bash
   agent-lifecycle start --adapter <идентификатор> --text "Исследовать ошибку в кэше и подготовить проверенный план"
   ```

4. Прочитайте JSON-подтверждение. Исходный текст, исследование и планирование
   остаются доступными для проверки, пока план не утверждён и не зафиксирован.
   Встроенный профиль задаёт только ограниченные значения по умолчанию: он не
   запускает внешний инструмент и не разрешает менять исходный код.

Используйте `quick-change` для небольшой запланированной правки,
`research-review` для исследования и проверки плана, а
`feature-implementation`, если нужен полный маршрут через планирование,
реализацию и аудит. Полная матрица приведена в разделе [профили рабочего
процесса](../reference/workflow-presets.md).

## Для продвинутых пользователей

Атомарные команды позволяют контролировать каждый этап отдельно. Повторно
используемые локальные настройки описаны в разделе [профиль рабочего процесса
проекта](../reference/project-workflow-profile.md):

```bash
agent-lifecycle project preset inspect --preset feature-implementation
agent-lifecycle project preset validate --preset feature-implementation
agent-lifecycle project preset render \
  --preset feature-implementation \
  --adapter <идентификатор> \
  --out .alk/project-profile.json
agent-lifecycle project profile check --profile .alk/project-profile.json
```

Затем используйте команды плана, задачи, стратегии, рабочего цикла и аудита из
[справочника CLI](../reference/cli.md). В [руководстве по настройке рабочего
процесса](../reference/workflow-customization.md) описаны классы моделей,
локальная привязка модели хоста, промпты, тайм-ауты и ограничения повторов.
Подключайте [Review Mesh](review-mesh-workflow.md), когда несколько агентов или
моделей должны независимо исследовать, проверить или проаудировать один план,
не объединяя их нативные беседы.

Продвинутый маршрут допускает `--no-project-profile`, явную привязку манифеста
и lock-файла, компиляцию пакетов задач и обязательные аудиты реализации или
финальный аудит. Источником полномочий для риска, границ записи, обязательных
проверок и принятой доказательной базы остаётся зафиксированный план.

## Выбор маршрута

Начните с простого варианта, если достаточно одного адаптера и одной задачи с
проверенным планом. Выбирайте атомарный вариант, если проекту нужны постоянный
локальный профиль, несколько проверяющих, явная маршрутизация моделей,
ограничения этапов или передача работы между операторами. При изменении области
или требований рабочего цикла план можно обновить и зафиксировать заново.
