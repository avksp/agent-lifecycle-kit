# Ресурсы и безопасность в рабочих запусках

ALK должен помогать довести задачу до результата с подтверждениями, а не
тратить основную часть запуска на доказательство собственного процесса.
Выбирайте самый лёгкий режим жизненного цикла, который соответствует риску
задачи.

## Режим ресурса

- `light`: небольшие и низкорисковые правки с узкой областью владения.
- `standard`: обычные задачи по исправлению ошибок и доработке функций.
- `strict`: безопасность, риск потери данных, совместимость публичного API или
  сложная независимая проверка.
- `release`: изменения метаданных пакета, заметок релиза, тегов или
  публикационных артефактов.

Любой режим может использовать компактные артефакты контекста, отчёты об
использовании модели и ограничения запуска. Более строгие режимы добавляют
больше подтверждений, но это не должно скрывать расход:

```bash
agent-lifecycle metrics cost-check --receipt <lifecycle-cost-report.json>
```

Точные счётчики токенов должны поступать от принятого локального нормализатора
хоста. Данные тестовых образцов и консервативная оценка ядра остаются явно
оценочными и не подходят для S1/S2. Подробнее:
[локальный учёт токенов хоста](../reference/host-local-token-accounting.md).

Если требования процесса вышли за пределы режима, зафиксируйте причину. Сам по
себе дорогой запуск не является успехом: реализация и продуктовая проверка всё
равно должны пройти.

## Маленькие локальные модели

Для маленьких моделей сначала готовьте компактные снимки и артефакты:

- `goal summarize`: цель и следующий шаг;
- `runner status --target-window 4k-strict`: состояние выполнения;
- `report status-view --target-window 4k-strict`: обезличенный статус
  подтверждений;
- `metrics cost-check`: накладные расходы процесса.

Эти артефакты помогают выполнению. Они не заменяют полные подтверждения для
финальной проверки.

## Внешний контекст

Выгрузки внешней памяти являются подсказками, а не источником истины:

```bash
agent-lifecycle context external-import \
  --source work/context/project-memory.md \
  --citation "одобренная оператором выгрузка памяти проекта" \
  --out work/context/project-memory.external-context.json
```

Импортируйте только файлы, которые оператор выбрал явно. ALK не вызывает
MCP-серверы, сервисы поиска по базе знаний, провайдеров или CLI хостов, чтобы
получить память. Артефакты должны сохранять `sourceOfTruth: false`,
обезличивать секретоподобные значения и не раскрывать приватные локальные пути.

## Граница безопасности

Релизные и рабочие проверки должны соблюдать эти границы:

- не хранить приватные ключи, токены, cookie или локальные пути машины в
  отслеживаемых файлах;
- не использовать внешний контекст как доказательство жизненного цикла или
  источник истины;
- не повышать зрелость адаптера без подтверждений, привязанных к хосту;
- не заявлять одобрение публичного каталога или промышленную готовность без
  внешнего подтверждения;
- не переносить хост-специфичную семантику в общие контракты ядра.

Перед заявлением стабильного пакета используйте `agent-lifecycle contract check`
и релизные проверки безопасности. Зрелость адаптеров берите из матрицы
поддержки; доступность модели сама по себе не делает адаптер `VERIFIED`.
