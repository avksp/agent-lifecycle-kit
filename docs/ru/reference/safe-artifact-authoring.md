# Безопасное создание артефактов

В ALK 2.19 появились команды создания JSON без перезаписи и структурная проверка
плана только для чтения. Они используют существующие валидаторы, reviewed lock,
workflow и проверки evidence. Корректный JSON сам по себе не подтверждает
истинность данных и не разрешает исполнение.

## Создание и просмотр

```bash
agent-lifecycle task artifact-create --kind json --input advisory.json --out new/advisory.json
agent-lifecycle task artifact-inspect --input new/advisory.json --max-display-bytes 8192
```

`--input` содержит один структурированный JSON-объект; здесь разрешён pretty JSON.
Выходной файл создаётся эксклюзивно в каноническом формате. Повторяющиеся ключи,
нечисловые значения вместо конечных чисел, превышение размера/глубины, небезопасные
родители, симлинки, коллизии и секреты приводят к отказу. Размер полного
структурированного запроса ограничен 262144 байтами. Строгие контракты чтения
авторитетных артефактов сохраняются.

| Вид | Контекст | Значение |
| --- | --- | --- |
| `json` | Структурированный объект. | Только сериализация; `authoritative: false`. |
| `task-result` | `--state`, `--task`, текущая привязка задачи, worker и native claim набора изменений. | Существующая проверка результата; commit, независимый аудит и принятие выполняются отдельно. |
| `evidence` | Закрытый payload `agent-evidence-receipt.v1`. | Расчёт и проверка существующих digest; форма не подтверждает запуск команды и не принимает задачу. |

Пример типизированного результата:

```bash
agent-lifecycle task artifact-create --kind task-result --state work/run.state.json --task WS-01 --input result-input.json --out work/new-task-result.json
```

Наблюдения и идентичности задаёт вызывающий. ALK не выдумывает worker и не
превращает stdout в успешный receipt. FAIL, SKIPPED, замечания и неизвестный расход
сохраняют свой смысл. Неизвестная телеметрия — null, а не ноль. Локальные имена
исполнителей и аргументы команд сохраняются в привязанных данных; секреты
отклоняются. `--redact-advisory` действует только для обычного advisory JSON с `authorityClaimed: false` и
оставляет authority false; очистка не может «исправить» типизированную идентичность
с сохранением заявления об исходном digest.

`artifact-inspect` не создаёт отдельный pretty-файл с полномочиями оригинала.
Результат содержит исходный путь и канонический digest, ограниченный очищенный
просмотр и признак усечения. Допустимый размер просмотра — 256–65536 байт.
Очищенный или усечённый просмотр не заменяет исходный артефакт.

## Подготовка кандидата freeze

```bash
agent-lifecycle plan freeze-prepare --manifest plans/draft/plan.manifest.json --out candidates/review-01 --repository-root .
```

Нужен корректный DRAFT-пакет. ALK выполняет существующий planning preflight и
проверку границ вывода, учитывает объявленные файлы и создаёт новый кандидат.
Ограничения — до 64 файлов и 8 МиБ суммарно. JSON канонизируется, остальные байты
сохраняются. Переносятся только объявленные пути пакета. Входы и старые lock-файлы
не изменяются.

Кандидат содержит предлагаемые FROZEN-метаданные, зарезервированный путь
независимого review и receipt подготовки. Положительный review, lock и разрешение
на исполнение не создаются. Отсутствующие входы, обход путей, алиасы, превышение
лимитов и пересечение вывода с входами или frozen authority вызывают отказ до
создания каталогов. Нужен новый корень вывода; конкурентная запись не заменит
победителя.

«Неизменяемый кандидат» означает создание без перезаписи и обнаружение изменений
по digest. Это не защита ОС от владельца файла. Проверяйте точный кандидат, затем
используйте существующие `plan lock-create`, `plan verify`, компиляцию задач,
adoption и отдельное разрешение на исполнение. Новые изменения требуют нового
кандидата и review. Не создавайте фиктивный положительный review для демонстрации.

## Структурная проверка плана

```bash
agent-lifecycle plan verify --manifest candidates/review-01/plan.manifest.json --repository-root . --out work/verification.json --compact
```

`plan verify` — основная структурная проверка. Полный типизированный receipt
привязывает manifest, перечисляет проверки, стабильные коды блокеров и
ограниченный контекст: отсутствующий пакет/lock, traceability, ownership и
конфликты вывода. Исправление выбирается по подробностям соответствующей
проверки. Изменение authority требует нового кандидата. Например,
`plan-lock-required` у ещё не проверенного кандидата требует настоящего review
и создания lock, а не подделки отсутствующего файла. Семантический аудит остаётся
обязательным для выбранного SDD tier.

`--compact` требует `--out`: полный receipt остаётся доступен по пути и digest.
Вывод по умолчанию совместим с прежним. Подсказки не исполняют shell-исправления,
не разрешают работу и не создают второй `workflow nextAction`. Повторяйте успешные
проверки только при изменении их зависимостей. Сохраняйте расходы и валидные
результаты после истечения времени или превышения лимита.

## Поиск часто используемых схем

```bash
agent-lifecycle schema list --scope core
agent-lifecycle schema show agent-artifact-authoring-request.v1
```

Небольшой core-набор указывает реальные контекстные валидаторы создания
артефактов, закрытых evidence receipt, положительного review плана и подготовленных
сырых ответов ревьюера. `schema list` сохраняет полный прежний реестр, `schema show`
сохраняет интерфейс. Описательная схема не даёт полномочий на исполнение.
Идентичности между файлами, актуальность исходников, независимое суждение и
принятие по-прежнему требуют соответствующих runtime-проверок и контекста.

## Материалы ревьюера

Опциональный переносимый индекс чтения и контракт сырого ответа описаны в
[Review Mesh](review-mesh.md#bounded-review-handoff). Подготовка проверяет локальные
входы и создаёт пакеты; она не запускает ревьюеров и не подтверждает доставку.
Сырой `reviewer-output.v1` отличается от нормализованного
`agent-review-mesh-result.v1`.

Роли ALK, хоста, модели, репозитория и независимого ревьюера описаны в
[границах SDLC](../architecture/sdlc-boundary.md).
