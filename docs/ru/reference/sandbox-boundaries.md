# Границы песочницы

Границы песочницы — это необязательный слой структурированных подтверждений для
ограничений среды выполнения: файловой системы, сети, процессов и окружения. Он
отделён от разрешённых путей записи в Git.

## Разделение границ

`agent-worktree-attempt-receipt.v1` подтверждает, что задача изменила только
разрешённые пути репозитория в изолированном рабочем дереве. Этот артефакт не
доказывает, что хост заблокировал сеть, запуск процессов, чтение переменных
окружения или доступ к файлам вне репозитория.

`agent-sandbox-receipt.v1` фиксирует ограничения среды выполнения:

- `filesystem`: ограничения хоста или ОС для файловой системы.
- `network`: запрет, фильтрация или другой контроль сетевого доступа.
- `process`: контроль запуска процессов и дочерних процессов.
- `environment`: контроль доступа к переменным окружения и секретам.
- `enforcement.source`: кто обеспечил ограничение: `HOST`, `OS`,
  `CONTAINER`, `ADAPTER`, `EXTERNAL`, `UNKNOWN` или `UNSUPPORTED`.

Обвязка реального хоста может при необходимости передать учётные данные
провайдера из приватного файла окружения оператора. Это граница окружения, а не
метаданные адаптера: оператор явно перечисляет каждое разрешённое имя через
`--host-env-allow`, обвязка передаёт дочернему процессу хоста только эти имена,
а артефакты содержат только `agent-host-env-file-redacted.v1`. Значения
секретов и полные локальные пути к файлу окружения не являются допустимым
содержимым артефакта.

Неизвестная поддержка фиксируется явно. Артефакт или описание возможности может
быть валидным со `status: UNKNOWN`, но рискованная задача, для которой
подтверждение песочницы обязательно, по умолчанию принимает только `PASS`.

Частичное ограничение фиксируется в том же каноническом
`agent-sandbox-receipt.v1`. Например, частичное покрытие дерева процессов Windows
можно записать как `boundaries.process.details.partialContainment` с описанием
покрытия и ограничений. Такой артефакт получает `sandboxStatus: UNKNOWN`, если
план задачи явно не разрешил этот статус; его нельзя повышать до `PASS` только
из-за частично заявленной границы.

Подтверждение прокси для учётных данных также остаётся внутри деталей границы
песочницы. Артефакт может хранить локальный для хоста класс источника, границу
прикрепления, разрешённые имена переменных и заглушку вроде
`<credential-proxy>`, но не значения секретов и не полный путь к приватному
файлу окружения.

## Политика

`agent-sandbox-requirement.v1` падает закрыто. Политика по умолчанию требует
проходящий артефакт песочницы для рискованных классов задач: `S2`, `security`,
`release`, `external-environment`, `architecture` и `performance`.

Задача может включить требование напрямую:

```json
{
  "id": "WS-security-01",
  "tier": "S1",
  "executionPolicy": {
    "sandbox": {
      "required": true,
      "acceptedSandboxStatuses": ["PASS"]
    }
  }
}
```

Если подтверждение песочницы обязательно и отсутствует, проверка возвращает
`sandbox-receipt-required`. Если артефакт структурно валиден, но имеет
`sandboxStatus: UNKNOWN`, проверка возвращает `sandbox-receipt-not-accepted`.
Планы, которые намеренно принимают частичное ограничение, могут задать
`acceptedSandboxStatuses` на уровне задачи, например `["PASS", "UNKNOWN"]`.

## Возможности адаптеров

Дескриптор и манифест возможностей адаптера используют
`agent-sandbox-capability.v1`. Текущие адаптеры заявляют `status: UNKNOWN` и
`verified: false`, пока нет отдельного артефакта реальной проверки песочницы.
Это не смешивает зрелость адаптера с гарантией песочницы ОС.

Адаптер может заявить более точный статус только при наличии подтверждений по
всем границам среды выполнения и источнику принудительного ограничения.
Манифест возможностей обязан совпадать с дескриптором; расхождение приводит к
`FAIL`.

## Публичные контракты

- `agent-sandbox-receipt.v1`
- `agent-sandbox-receipt-validation.v1`
- `agent-sandbox-requirement.v1`
- `agent-sandbox-requirement-validation.v1`
- `agent-sandbox-capability.v1`
- `agent-sandbox-capability-validation.v1`

Эти контракты не заявляют промышленную готовность. Для такого продвижения
остаётся обычный путь релизных подтверждений.
