# Сравнение проекта

Agent Lifecycle Kit (ALK) — не кодовый агент и не платформа запуска моделей.
Это слой управления задачей: черновой вход, проверенная спецификация,
зафиксированный план, работа в заданных границах, аудит реализации и итоговое
подтверждение.

Источником правды остаётся зафиксированный план ALK. Внешние спецификации,
навыки, память, среды запуска и кодовые агенты могут помогать, но для ALK они
являются черновым входом, внешним исполнителем или дополнительным контекстом.

## Коротко

| Класс проектов | Примеры | Что решают | Граница ALK |
| --- | --- | --- | --- |
| Кодовые агенты | SWE-agent, Aider, Cline, Continue | Меняют код и запускают проверки | ALK сам не пишет код; он задаёт план, границы, подтверждения и итоговую проверку вокруг исполнителя. |
| Среды запуска агентов | Omnigent, OpenHands, Archon | Запускают агентов, координируют шаги, часто дают сервер или интерфейс | ALK оставляет выполнение у провайдера вне переносимого ядра. Управляемый запуск объявляется только дескриптором адаптера и не является брокером провайдеров. |
| Инструменты спецификации | OpenSpec, GitHub Spec Kit, BMAD-METHOD, Spec Kitty | Помогают описать, что нужно построить | ALK может импортировать такие материалы как черновик; главным становится только проверенный и зафиксированный план ALK. |
| Библиотеки навыков и методик | superpowers, AGENTS.md, agent-skills | Направляют поведение агента инструкциями | ALK добавляет проверяемые схемы, файл блокировки, подтверждения и контрольные точки. |
| Системы памяти | gbrain, mem0, zep | Дают долговременный контекст и поиск по знаниям | ALK может использовать внешнюю память как обезличенный контекст, но не как доказательство или источник правды. |

## Где ALK полезен

ALK подходит, когда нужно:

- сохранить один процесс работы при смене CLI или модели;
- доказать завершение задачи, а не только получить правку;
- зафиксировать границы записи, критерии приёмки и подтверждения;
- использовать маленькие или локальные модели с компактным заданием и
  повторяемыми проверками;
- организовать дополнительную проверку несколькими исполнителями без
  превращения ядра в брокер провайдеров;
- продолжать долгую задачу между сессиями без потери плана и подтверждений.

## Что есть в ALK

В ALK также есть дополнительные возможности:

- управляемые сессии адаптеров и приём задачи принимают текст, Markdown-файлы и
  зафиксированные запросы на запуск, а правило запуска хоста остаётся в
  дескрипторе адаптера; встроенные дескрипторы сейчас объявляют
  `WRAPPER_ONLY` для управляемого запуска;
- материалы OpenSpec, Spec Kit, BMAD, Spec Kitty и похожих форматов
  импортируются как черновой вход и становятся обязательными только после
  проверки и фиксации плана ALK;
- дополнительная групповая проверка создаёт задания проверяющим, принимает
  обезличенные результаты, объединяет выводы и проверяет кворум только когда
  зафиксированный план явно включает такой режим;
- захват событий адаптера, внешний контекст памяти, статус цели без записи и
  рекомендация расследования ошибок добавляют подтверждения, но не превращают
  ALK в брокер моделей или базу знаний.

## Примеры проектов

| Проект | Сходство с ALK | Главное отличие |
| --- | --- | --- |
| oh-my-openagent | Улучшает долгую работу агента через навыки, режимы и командные сценарии на уровне хоста. | Глубже входит в среду хоста и выполнение агента; ALK остаётся внешним переносимым слоем жизненного цикла и подтверждений. |
| bmad-loop | Ближайший сосед по детерминированному циклу: делает упор на управление без модели, проверки и возобновляемую работу. | Сам запускает CLI хоста в своём цикле; ALK держит запуск на границе адаптера или обёртки и покрывает путь от спецификации до доказательства. |
| goalbuddy | Похож по удержанию цели и видимому циклу доказательства. | Это более лёгкий сценарий доски цели; ALK добавляет SDD, фиксацию плана, владение файлами, аудит, адаптеры, дополнительную групповую проверку и финальное доказательство. |

## Когда ALK может быть лишним

ALK может быть избыточен для небольшой одноразовой правки.

## Как совмещать с другими инструментами

| Внешний слой | Как использовать с ALK |
| --- | --- |
| Документы OpenSpec, Spec Kit, BMAD и Spec Kitty | Импортировать как черновой вход, затем проверить и зафиксировать план ALK. |
| Codex, Claude Code, Cursor, Gemini CLI, Goose, Grok Build, Hermes, Kimi Code, OpenCode, OpenInterpreter, Pi, Qwen Code | Использовать как внешних исполнителей через адаптеры и локальные профили; текущие встроенные дескрипторы имеют `WRAPPER_ONLY` для управляемого запуска. |
| SWE-agent или другой кодовый агент | Рассматривать как внешнего исполнителя, чей результат всё равно проверяется через ALK. |
| Среда запуска или web-интерфейс | Оставить запуск, интерфейс и совместную работу снаружи ядра; в ALK передавать подтверждения или результаты. |
| Система памяти | Импортировать обезличенный контекст с ссылками и отпечатками источника, без права заменять доказательства. |
| Библиотека навыков | Использовать как инструкцию, а фактическую работу связывать с контрактами и контрольными точками ALK. |

## Главная граница

ALK должен оставаться слоем проверяемого завершения работы. Он может принимать
черновики, показывать прогресс, готовить задания для нескольких проверяющих и
проверять подтверждения, но не должен становиться брокером моделей,
обязательным web-интерфейсом, базой знаний, вторым движком выполнения или
инструментом автоматического повышения зрелости адаптера.
