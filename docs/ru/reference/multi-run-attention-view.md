# Представление внимания по нескольким запускам

В Release 2.3 добавлено необязательное представление только для чтения для
операторов, которые координируют несколько запусков ALK. Команда читает
только явно переданные корни запусков и объединяет ограниченные сведения о
состоянии, журнале событий, индексе подтверждений и объявленных путях
владения.

## Команда

```bash
agent-lifecycle report multi-run \
  --project-root . \
  --run-root work/release-a \
  --run-root work/release-b \
  --out work/multi-run-view.json
```

Лимиты `--max-runs` и `--max-bytes-per-run`, а также лимит записей журнала
фиксируются в возвращаемом поле `limits`. Для воспроизводимой проверки
устаревшей попытки в тесте или ревью используйте
`--now 2026-08-25T00:00:00Z`. Допустим и псевдоним отчёта `attention`.

Результат использует `agent-multi-run-attention-view.v1`. Каждый элемент
внимания содержит идентификатор запуска, ревизию плана, исходную ревизию,
ревизию состояния и стабильный код причины. Коды описывают блокер,
необходимость действия пользователя, ожидающее ревью, устаревшую попытку,
ошибочное подтверждение и завершённый запуск. Повреждённый или недоступный
источник получает `SOURCE_UNAVAILABLE` и никогда не считается успешным.

## Пересечения и полномочия

Общие между выбранными запусками объявленные пути владения или изменённые
файлы попадают в `overlaps` с `authorityRetained: true`. Это только
рекомендательный сигнал конфликта: команда не выбирает владельца, не сливает
файлы, не авторизует задачу, не разрешает конфликт и не меняет состояние
рабочего цикла. Единственным источником полномочий остаются зафиксированный
план и его состояние.

Команда отклоняет корни вне `--project-root`, компоненты с символическими
ссылками, недопустимые относительные пути и входы, превышающие лимиты байтов
или записей. Вывод редактируется и сортируется детерминированно. Без
`--run-root` команда возвращает пустое представление со статусом PASS, не
создаёт файл и не сканирует проект.

Команда не запускает модель, процесс хоста, сеть, демон, базу данных или
планировщик. Это операторский отчёт, а не оркестратор нескольких агентов.
