# Снимки контекста и восстановление после сжатия

ALK может сохранить краткое типизированное состояние продолжения, когда
длинная сессия внешнего инструмента приближается к сжатию контекста. Снимок —
это локальный рабочий артефакт. Он помогает восстановить текущий контекст, но
утверждённый план, состояние рабочего процесса и принятые подтверждения
остаются источником правды.

## Режимы создания

| Режим | Когда создаётся | Что означает статус |
| --- | --- | --- |
| `MILESTONE` | На включённом переходе рабочего процесса ALK | ALK локально создал снимок на объявленной контрольной точке. |
| `AGENT_REQUESTED` | По явному запросу оператора или внешнего инструмента | Вызывающая сторона попросила ALK сохранить структурированную сводку. |
| `NATIVE_HOOK` | Адаптер передал принятое подтверждение события перед сжатием | Событие внешнего инструмента зафиксировал адаптер, а не ядро ALK. |
| `UNAVAILABLE` | Доступного маршрута создания нет | Автоматическое наблюдение за сжатием не заявляется. |

Одной инструкцией или установкой плагина нельзя подтвердить `NATIVE_HOOK`. Для
этого нужны принятая возможность адаптера и соответствующая нейтральная
квитанция события.

## Создание снимка

На вход подаётся JSON-объект с ограниченной сводкой. В него можно включить
текущие решения, ограничения, блокеры, изменённые файлы и следующий шаг. В нём
не должно быть полной переписки или полей, выдающих полномочия.

```bash
agent-lifecycle context checkpoint \
  --session session-123 \
  --state work/run.state.json \
  --plan tasks/current/plan.manifest.json \
  --input work/context/decisions.json \
  --reason agent-requested \
  --out .alk/context/checkpoints/session-123.json
```

Команда создаёт `agent-context-checkpoint.v1`. В него входят идентификаторы
сессии и запуска, ревизия и отпечаток плана, ревизия состояния, исходная
ревизия и отпечатки связанных артефактов. Значения, похожие на секреты, и
приватные пути очищаются; поля полномочий промпта, инструментов, фиксации,
приёмки и реализации отклоняются.

Для режима `NATIVE_HOOK` во входном JSON должен быть объект
`nativeHookEvidence` с полями `status: PASS`, `accepted: true`,
`producerBoundary: adapter-owned`, а также с отпечатками квитанций возможности
адаптера и события. ALK сохраняет его как `captureEvidence` и отклоняет снимок,
если подтверждение адаптера отсутствует или некорректно.

## Восстановление после сжатия

```bash
agent-lifecycle context restore \
  --checkpoint .alk/context/checkpoints/session-123.json \
  --state work/run.state.json \
  --session session-123 \
  --out work/context/continuation.json
```

Восстановление проверяет происхождение текущего состояния, отпечаток, статус
очистки и ограничения размера. При успехе возвращается
`agent-context-continuation.v1` — ограниченный пакет со сводкой и ссылками.
Пакет всегда содержит `implementationAuthorized: false` и
`proofAuthority: none`. Устаревший или изменённый снимок блокируется и не
меняет состояние рабочего процесса.

## Политика контрольных точек

Утверждённый план может включить создание снимков на контрольных точках:

```json
{
  "enabled": true,
  "required": false,
  "milestoneEvents": ["plan-adopted", "task-completed"],
  "maxCheckpointsPerRun": 64,
  "retentionPolicy": "retain-latest-with-explicit-delete"
}
```

Нормализованная политика сохраняется при принятии плана. Единственная
контрольная точка в `workflow/operation_kernel.commit_state` выполняется до
записи состояния. При обязательном снимке ошибка останавливает переход; при
необязательном фиксируется некритичное предупреждение, а переход сохраняется.
Ключ идемпотентности объединяет идентификатор операции, ревизию состояния и
тип события, поэтому повтор того же перехода не создаёт второй снимок.

## Хранение и безопасность

Снимки хранятся в `.alk/context/checkpoints`. Запись выполняется атомарно, а
для одного запуска сохраняется не более 64 артефактов. Очистка удаляет только
самые старые файлы внутри этого каталога. Ядро не вызывает модель, провайдера,
сеть, подпроцессы или CLI хоста. Снимок сохраняет непрерывность контекста, но
не заменяет план, проверку, подтверждение приёмки или финальное доказательство.

## Влияние на токены и качество

Создание снимка детерминировано и не расходует токены модели. Ограниченный
пакет после восстановления уменьшает повторное чтение длинной переписки. Он
помогает сохранить ход работы, но не заменяет требования и тесты: их полнота
по-прежнему определяется спецификацией, планом и подтверждениями приёмки.
