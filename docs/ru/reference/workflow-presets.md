# Профили рабочего процесса

[English version](https://github.com/avksp/agent-lifecycle-kit/blob/main/docs/reference/workflow-presets.md)

Профили рабочего процесса — это необязательные начальные настройки для
проекта. Они помогают быстро выбрать распространённый маршрут, но не меняют
полномочия профиля проекта, зафиксированного плана и отдельных команд
жизненного цикла.

## Встроенные профили

| Профиль | Режим по умолчанию | Риск по умолчанию | Review Mesh | Полномочия на реализацию |
| --- | --- | --- | --- | --- |
| `quick-change` | `implement` | `S0` | `off` | Требуется зафиксированный план |
| `research-review` | `research` | `S1` | `parallel-research-synthesis` | Реализация исключена |
| `feature-implementation` | `implement` | `S2` | `implementation-audit-panel` | Требуется зафиксированный план |

Значения Review Mesh — это действующие идентификаторы режимов. По умолчанию
они имеют рекомендательный характер; блокирующая проверка включается только
если это явно указано в зафиксированном плане. Профили не содержат провайдера,
имени модели, аккаунта, промпта, секрета или исполняемой команды. Нижняя
граница качества определяется существующей политикой качества и планом;
отдельного поля качества в профиле нет.

Ограничения этапов являются версионируемыми данными профиля:

| Профиль | Этапы и ограничения (`попытки` / `вызовы` / `секунды`) |
| --- | --- |
| `quick-change` | `implementation` 2 / 8 / 900; `audit` 1 / 4 / 900 |
| `research-review` | `research`, `planning`, `review` 2 / 8 / 1800 |
| `feature-implementation` | `planning` 2 / 8 / 1800; `implementation` 3 / 12 / 3600; `audit` 2 / 8 / 1800 |

В `research-review` намеренно нет этапа реализации. Два других профиля
описывают маршрут с реализацией, но сам профиль не разрешает менять исходный
код: для этого по-прежнему нужны зафиксированный план и его lock-файл.

## Просмотр и проверка

Показать доступные профили:

```bash
agent-lifecycle project preset list
```

Посмотреть один профиль без записи файла:

```bash
agent-lifecycle project preset inspect --preset feature-implementation
```

Проверить его контракт, ограничения и границы безопасности:

```bash
agent-lifecycle project preset validate --preset feature-implementation
```

Эти команды выполняются детерминированно: они не вызывают модель, не запускают
внешний инструмент и не изменяют профиль проекта.

## Создание локального профиля

Запишите черновик в явно указанный путь, если нужно использовать профиль как
локальную настройку проекта:

```bash
agent-lifecycle project preset render \
  --preset research-review \
  --adapter <adapter-id> \
  --out .alk/project-profile.json
```

На выходе получается обычный файл `agent-project-workflow-profile.v1`.
Команда не выбирает путь автоматически и не перезаписывает существующий файл.
`.alk/project-profile.json` хранится локально, исключён из Git и не является
источником истины проекта.

После создания проверьте профиль:

```bash
agent-lifecycle project profile check --profile .alk/project-profile.json
```

## Одноразовый запуск с профилем

Для одного запуска профиль можно применить без создания файла:

```bash
agent-lifecycle start \
  --adapter <adapter-id> \
  --preset research-review \
  --text "Изучить платёжный поток и подготовить проверенный план реализации"
```

Задача остаётся в обычном процессе ALK: приём, проверка и фиксация плана не
пропускаются. Профиль задаёт только значения по умолчанию и не запускает
внешний инструмент без явного `--launch`.

## Приоритеты и расширенная настройка

Итоговые настройки определяются в таком порядке:

1. обязательные правила жизненного цикла и зафиксированный план;
2. явно переданные значения командной строки;
3. явно заданные поля профиля проекта;
4. значения встроенного профиля.

Зафиксированный план может повысить уровень риска, потребовать Review Mesh,
сохранить границы записи и обязательные проверки. Профиль не может ослабить
эти требования. Явное значение в профиле или командной строке может усилить
ограничения; попытка понизить требование зафиксированного плана отклоняется.

Профили не заменяют атомарные команды. Продвинутый пользователь может создать
профиль, изменить только поддерживаемые локальные поля, проверить его по
манифесту и lock-файлу, а затем использовать отдельные команды жизненного
цикла из [справочника CLI](cli.md) и [руководства по настройке рабочего
процесса](workflow-customization.md).

## Контракты и безопасность

Для данных профиля и результатов команд используются стабильные схемы:

- `agent-project-workflow-preset.v1`;
- `agent-project-workflow-preset-validation.v1`;
- `agent-project-workflow-preset-list.v1`;
- `agent-project-workflow-preset-operation.v1`;
- `agent-project-workflow-preset-render-receipt.v1`.

Поиск, проверка и создание профиля выполняются только с локальными данными.
Пути должны оставаться внутри корня проекта, запись выполняется один раз, а
поля провайдера, модели, учётных данных, промпта, URL, исполняемой команды и
другие чувствительные поля отклоняются.
