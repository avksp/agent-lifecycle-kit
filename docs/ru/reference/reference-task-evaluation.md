# Оценка по эталонным задачам

Команда `agent-lifecycle benchmark evaluate` сравнивает переданные артефакты ALK
с версионируемым детерминированным правилом эталонной задачи. Это локальная
проверка без записи: она не вызывает модель, не запускает внешний инструмент,
не меняет состояние рабочего цикла и не объявляет реальный проект готовым к
промышленной эксплуатации.

## Команда

```bash
agent-lifecycle benchmark evaluate \
  --suite benchmarks/reference-tasks/manifest.json \
  --artifact work/benchmark/submission.json \
  --out work/benchmark/evaluation.json
```

Команда выводит и при необходимости сохраняет
`agent-reference-task-evaluation.v1`. Выходной файл создаётся только один раз.

## Входной артефакт

Вход соответствует схеме `agent-reference-task-submission.v1`:

```json
{
  "schemaVersion": "agent-reference-task-submission.v1",
  "taskId": "rt01-planning",
  "taskVersion": "1.0.0",
  "accepted": true,
  "evidence": {
    "planValidation": {"schemaVersion": "agent-plan-validation.v1", "status": "FROZEN"},
    "completenessValidation": {"schemaVersion": "agent-plan-completeness-validation.v1", "status": "PASS", "blockers": []},
    "acceptanceValidation": {"schemaVersion": "agent-acceptance-checklist-validation.v1", "status": "PASS", "missingInMarkdown": [], "extraInMarkdown": [], "linkMismatches": []}
  },
  "productionPromotionClaimed": false
}
```

Для измерения токенов и времени добавьте существующий
`agent-usage-export.v1` в `evidence.usageExport`. Для подсчёта повторов добавьте
`agent-task-outcome-index.v1` в `evidence.outcomeIndex`. Оценщик использует эти
артефакты, но не заменяет их источник полномочий.

Вложенность входных подтверждений ограничена 64 уровнями, а их общее число
значений — 100 000. При превышении любого ограничения команда возвращает
типизированную ошибку ALK до проверки правила и вычисления отпечатка.

## Семейства правил

| Задача | Условие успешной проверки |
| --- | --- |
| `rt01-planning` | Зафиксированный план, успешная проверка полноты и отсутствие расхождений в критериях приёмки. |
| `rt02-architecture-review` | Успешный кворум групповой проверки, все обязательные роли и отсутствие нерешённых блокирующих замечаний. |
| `rt03-bug-forensics` | Связанная цепочка воспроизведения и регрессионного подтверждения с совпадающими отпечатками. |
| `rt04-s1-managed-task` | Полный результат задачи, успешные команды и принятый независимый аудит реализации. |
| `rt05-s2-evidence-task` | Готовое финальное подтверждение, успешные проверки реализации и целостности, а также требуемый планом кворум. |

Правило читает только типизированные артефакты, созданные вне оценщика. Оно не
анализирует подсказки модели и не просит автора результата оценить самого себя.

## Измерения

Артефакт оценки содержит:

- число пройденных и общее число детерминированных условий;
- отдельные группы токенов `ATTESTED`, `ESTIMATED` и `MISSING`;
- время из записей экспорта использования;
- число повторов из индекса результатов задач;
- явный перечень отсутствующих измерений.

При смешанной уверенности `tokens.headline.total` равен `null`. Потребитель
должен читать отдельные группы и не складывать подтверждённые и оценочные
значения в число без обозначения качества данных.

## Ложная приёмка

Если `accepted` равен `true`, но правило не выполнено, результат содержит:

```json
{"status":"FAIL","summary":{"falseAcceptanceCount":1}}
```

Команда завершается штатно, потому что корректно построила отрицательный
результат. Автоматизация должна проверять состояние и счётчик в артефакте.
Ошибки команды или входных данных проходят через обычный механизм ошибок ALK.

## Безопасность и границы

Результат хранит отпечатки, размеры, типизированные проверки, измерения и
обезличенные сводки. Текст задачи и переписка не копируются. Общий механизм
обезличивания удаляет типовые секреты и приватные локальные пути.
`evaluationDigest` вычисляется по очищенному результату вместе с состоянием
обезличивания, а не по исходным подтверждениям. Синтетическая задача
не заменяет промышленные подтверждения, зрелость адаптера или решение о публикации.
