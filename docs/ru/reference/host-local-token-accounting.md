# Локальный учёт токенов хоста

ALK не переносит телеметрию конкретных моделей и поставщиков в общее ядро.
Адаптер может объявить локальный нормализатор расхода: он читает один
ограниченный артефакт хоста и формирует существующее подтверждение
`agent-lifecycle-model-usage-receipt.v1`. Дескриптор использует контракт
`adapter-local-usage-normalizer.v1`.

Так разделяются две ответственности:

- нормализатор адаптера определяет, какие счётчики действительно сообщил хост;
- ядро проверяет происхождение, привязку к маршруту, ограничения расхода и
  допустимость этих данных для S1/S2.

## Уровни подтверждения

| Состояние | Значение | Допустимо для S1/S2 |
| --- | --- | --- |
| `UNSUPPORTED` | Локальный нормализатор не объявлен. Ядро может показать консервативную оценку. | Нет |
| `FIXTURE_ONLY` | Разбор проверен на ограниченных тестовых образцах, но не подтверждён для диапазона версий реального хоста. | Нет |
| `QUALIFIED` | Для нормализатора указан диапазон версий хоста и принято независимое подтверждение. | Да, только при `source: host` и `status: ATTESTED` |

Зрелость адаптера и состояние нормализатора токенов не связаны автоматически.
Например, Qwen Code остаётся адаптером `VERIFIED`, но вынесенный нормализатор
пока имеет состояние `FIXTURE_ONLY`. Ранее принятое подтверждение жизненного
цикла не считается доказательством для нового контракта разбора.

## Привязка подтверждения

Адаптер вкладывает подтверждение использования модели в результат операции
хоста. Схема `agent-host-operation-receipt.v1` при этом не меняется.
Сопутствующее подтверждение связывает:

- операцию и отпечаток решения о маршруте;
- адаптер и хост;
- нейтральный класс модели и отпечаток локальной настройки модели;
- SHA-256, размер и формат исходного артефакта без локального пути;
- состояние нормализатора и отпечаток его исходного файла.

Исходный JSONL, запросы, ответы, секреты и локальные пути в переносимое
подтверждение не копируются. Идентификатор сеанса сохраняется только тогда,
когда соответствует ограниченному формату непрозрачного идентификатора.

## Поддерживаемые нормализаторы

| Адаптер | Артефакт | Состояние нормализатора |
| --- | --- | --- |
| Gemini CLI | `stream-json` | `FIXTURE_ONLY` |
| Kimi Code | `stream-json` | `FIXTURE_ONLY` |
| Qwen Code | `stream-json` | `FIXTURE_ONLY` |
| Остальные встроенные адаптеры | Контракт не объявлен | `UNSUPPORTED` |

Все три нормализатора находятся в
`adapters/<adapter>/usage_normalizer.py`. Исполнитель адаптера и испытательный
стенд загружают один и тот же файл через защищённый загрузчик. Он отклоняет
выход за каталог адаптера, символьные ссылки и несовпадение пути с
дескриптором.

Проверить объявления и границы разбора:

```bash
python tools/release/validate_host_usage_normalizers.py \
  --adapter-root adapters \
  --evidence work/validation/host-usage-normalizers.json

agent-lifecycle adapter validate \
  --descriptor adapters/qwen-code/adapter.descriptor.json
```

Проверить подтверждённый расход по маршруту и ограничениям:

```bash
agent-lifecycle model usage-check \
  --receipt work/run/model-usage.json \
  --route-decision work/run/model-route.json \
  --budget-targets conformance/core/budget-targets.v1.json
```

Числа из тестового образца точны для этого образца, но для гейтов жизненного
цикла они остаются данными `ESTIMATED`. Одна метка состояния не может повысить
их до подтверждения реального хоста.

## Консервативная оценка

Если точных данных хоста нет, ядро использует заметную верхнюю оценку: один токен на каждый байт
исходного артефакта. Она помечается как
`source: core-estimate`, `status: ESTIMATED`. Агрегатор считает данные
подтверждёнными только при одновременном наличии `source: host` и
`status: ATTESTED`.

Учёт токенов остаётся учётом ресурсов, а не цены. Хост может сообщить денежные
метаданные, но ALK не содержит канонического каталога тарифов поставщиков.
