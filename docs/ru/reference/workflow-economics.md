# Экономика рабочего процесса

Экономика рабочего процесса сравнивает явные неизменяемые артефакты учёта, не
передавая полномочия сравнению или рекомендации. Она показывает, уменьшили ли
изменения оркестрации измеренный расход при сохранении той же нагрузки и не
менее строгого уровня проверок.

## Сравнение артефактов

Используйте два артефакта с устойчивой идентичностью нагрузки, наблюдаемой
идентичностью реализации, результатами гейтов и метриками ресурсов:

```bash
agent-lifecycle metrics workflow-compare \
  --before tests/metrics/fixtures/release-2-8-continuation-baseline.json \
  --after tests/metrics/fixtures/release-2-10-continuation-baseline.json \
  --comparison-pair tests/metrics/fixtures/release-2-10-continuation-comparison-pair.json \
  --out work/workflow-comparison.json
```

По умолчанию должны совпадать устойчивые идентичности нагрузки и реализации.
Различающиеся source revision или версия допустимы только тогда, когда оба
неизменяемых артефакта содержат одну каноническую заранее объявленную пару
before/after и точно соответствуют её implementation tuples. Переданная
вызывающей стороной метка, одинаковые роли, изменённое тело пары, позднее
объявление или неверный digest не создают сопоставимость.

Результат имеет статус `IMPROVED`, `REGRESSED`, `MIXED` или
`NO_COMPARABLE_BASELINE`. Дельты метрик значимы только для измеренных исходных
значений и при сохранении всех обязательных гейтов на том же или более строгом
уровне. Отсутствующая телеметрия остаётся `UNAVAILABLE`; производные статусы
агрегатов `MIXED` и `PARTIAL` не становятся доступностью исходного значения.

## Формирование рекомендации

```bash
agent-lifecycle metrics workflow-recommend \
  --comparison work/workflow-comparison.json \
  --task-shape release \
  --current-mode release \
  --required-mode release \
  --protected-work \
  --out work/workflow-recommendation.json
```

Рекомендация детерминирована и имеет только справочный характер. Она сохраняет
`advisoryOnly: true`, `autoApply: false` и `authorityClaimed: false`, не может
менять policy, workflow, приёмку или обязательные гейты. Защищённые задачи
безопасности, архитектуры, качества и выпуска нельзя упростить по среднему
значению или кажущейся экономии.

Обе команды работают локально и создают файл только один раз. Они не запускают
модель, хост-процесс или сетевой вызов и не переписывают артефакты прошлых
релизов.
