# Необязательный профиль анализа безопасности

ALK предоставляет необязательный нейтральный к провайдеру профиль для
ограниченного расследования безопасности. Он объединяет модель угроз,
нормализацию находок, подтверждение эксплуатируемости, устранение дублей,
доработку и независимую проверку. Это не сканер уязвимостей и по умолчанию он
не запускает код эксплуатации.

## Граница по умолчанию

Профиль имеет статус `OPTIONAL` и по умолчанию выключен. Профиль или
импортированная находка не получают полномочий workflow, не принимают задачу
и не запускают процесс хоста. Находка остаётся явно недоверенным свидетельством,
пока не пройдёт проверку исходной ревизии, происхождения и очищенных локаторов.

Политика выполнения по умолчанию:

- требуется явное включение в замороженном плане;
- перед активным воспроизведением нужны подтверждение песочницы и ограниченное
  разрешение;
- вызовы модели, сети и процессов хоста по умолчанию запрещены;
- импортированное свидетельство не может само повысить себя до уязвимости или
  решения о публикации.

Для статических материалов достаточно безопасного пути только для чтения:

```bash
agent-lifecycle quality security-profile --out work/security-profile.json
agent-lifecycle import security-findings \
  --source findings.sarif \
  --expected-source-revision <revision> \
  --out work/security-findings.json
agent-lifecycle quality security-finding-check \
  --candidate work/security-findings.json \
  --expected-source-revision <revision> \
  --out work/security-findings-validation.json
agent-lifecycle report security-analysis \
  --finding work/security-findings.json \
  --profile \
  --source-revision <revision> \
  --expected-source-revision <revision> \
  --out work/security-analysis-report.json
```

Импорт принимает нормализованные находки и ограниченный SARIF. Отчёт сохраняет
статус проверки, идентификаторы находок и ссылки на свидетельства, но сохраняет
`trusted: false`, `authorityClaimed: false` и
`productionPromotionClaimed: false`.

## Доработка находки высокой серьёзности

План может передать `extensions.securityAnalysis.implementationAudit` в каждую
принятую задачу. Если политика относится к высокой серьёзности, реальная
граница приёмки задачи отклоняет свидетельство только от исполнителя с кодом
`security-analysis-verification-required`. Для приёмки требуется новое
независимое назначение проверки с совпадающими run, task, attempt, plan и
исходной линией. Пакет Review Mesh может предоставить назначение проверяющего,
но полномочия остаются у границы приёмки workflow.

Неудачные, устаревшие, спорные и неполные свидетельства сохраняются как
свидетельства неудачной проверки. Они не превращаются в приёмку молча. Для
доработки используется существующий переход workflow и новая попытка, а не
редактирование прошлого артефакта.

## Безопасное выполнение и раскрытие

Импортированная находка или профиль сами по себе не запускают воспроизведение.
Активный шаг должен быть объявлен замороженным планом, разрешён для точной
операции, связан с подтверждением песочницы и ограничен по попыткам, вызовам,
времени и объёму свидетельств. Команда провайдера, модель и учётные данные
остаются за пределами ядра.

Не помещайте секреты, подробности частного инцидента, payload эксплуатации или
сырой вывод хоста в переносимые свидетельства. Используйте пути относительно
репозитория или публичные HTTP(S)-локаторы после проверки. Абсолютные локальные
пути, file-URI, учётные данные и значения локаторов, похожие на секреты,
отклоняются или очищаются по общему контракту локаторов.

## Контракты

Основные контракты:

- `agent-security-analysis-profile.v1`;
- `agent-security-finding.v1` и конверты импорта/проверки;
- `agent-security-execution-gate.v1`;
- `agent-security-verification-assignment.v1`;
- `agent-security-analysis-audit.v1`.

Профиль является необязательным слоем свидетельств поверх существующего
workflow. Он не создаёт вторую машину состояний, не заменяет замороженный план
и не заявляет о запуске внешнего анализатора, если передан только его импортированный
результат.

См. также [публичные локаторы и редакцию](public-locators-and-redaction.md),
[аудит реализации](implementation-audit.md) и [внешние проверки проекта](external-verification-checks.md).
