# Независимая проверка для рискованных критериев

Релиз 2.1 добавляет контракт подтверждения для отдельных критериев. Он нужен,
когда важное утверждение требует проверки отдельным производителем, отдельной
линией реализации или другой ревизией источника. Возможность необязательна и
по умолчанию выключена. Обычные критерии ALK продолжают использовать прежние
детерминированные проверки и подтверждения ревью.

## Когда это нужно

Включайте независимую проверку только для критерия с достаточно высоким
риском, когда результата основного пути реализации недостаточно. Например:

- утверждение о безопасности или архитектуре проверяется отдельной
  реализацией проверки;
- область релиза сверяется с ревизией источника, которую не создавал
  исполнитель;
- граничный детерминированный тест должен иметь отдельного производителя и
  отдельную линию реализации.

Не добавляйте этот механизм к обычным критериям только ради большего числа
receipt. Требование входит в критерий до начала выполнения и не может быть
добавлено после результата только для его принятия или отклонения.

## Объявление требования

Критерий плана может содержать объект `independence` и маршрут подтверждения
через `independentEvidenceIds`:

```json
{
  "id": "AC-SECURITY-BOUNDARY",
  "independence": {
    "schemaVersion": "agent-independence-requirement.v1",
    "required": true,
    "requiredDimensions": ["producer", "implementation", "source"],
    "allowedMethods": ["deterministic-check", "human-review"],
    "prohibitedProducerClasses": ["implementation-worker"],
    "sourcePolicy": "exact-revision",
    "productionPromotionClaimed": false,
    "requirementDigest": "<digest предыдущих полей>"
  },
  "independentEvidenceIds": ["EV-SECURITY-BOUNDARY"]
}
```

Для создания объекта с digest используйте
`build_independence_requirement()`. Проверка полноты плана требует маршрут
подтверждения для каждого критерия с `required: true`.

Поддерживаются измерения производителя, реализации и источника. Политика
источника задаётся явно: `exact-revision` требует ожидаемую ревизию и линию
происхождения на гейте; `current-lineage` и `any-current` можно использовать,
если план сознательно разрешает такие границы.

## Запись подтверждения

`agent-independent-evidence.v1` содержит только ограниченные факты:

- digest критерия и требования;
- ревизию и digest линии происхождения источника;
- метод (`deterministic-check` или `human-review`);
- класс производителя и хэш идентичности;
- digest реализации;
- статус, находки и причину недоступности, если она есть.

Поля `rawReasoningStored`, `rawTranscriptStored` и
`productionPromotionClaimed` всегда имеют значение `false`. Скрытое
рассуждение, полный текст ревью, секреты и названия провайдеров не являются
переносимым подтверждением.

Валидатор проверяет digest требования, разрешённый метод, запрещённый класс
производителя, ожидаемую линию источника и digest основной реализации.
Повторное использование записи для другой ревизии либо общий производитель
или реализация дают ошибку проверки.

## Ревью и гейт

Пакет назначения Review Mesh несёт зафиксированное требование. Обязательный
критерий должен предоставить запись со статусом `PASS`, чтобы результат прошёл
Review Mesh или проверку кворума. `UNAVAILABLE`, устаревшие и повреждённые
записи блокируют этот критерий.

Необязательное требование остаётся рекомендательным: отсутствие подтверждения
не меняет полномочия несвязанных задач и запуска. Review Mesh по-прежнему не
запускает модель, CLI хоста или сетевой сервис; ограниченную запись создаёт
оператор или принадлежащая адаптеру обёртка, а ALK её проверяет.

## Границы безопасности и полномочий

Независимое подтверждение является дополнительной проверкой, а не вторым
источником полномочий рабочего процесса. Оно не меняет владение, не разрешает
команду, не обходит security-гейт, не повышает уровень адаптера и не заменяет
зафиксированный план. Источником полномочий остаются состояние workflow, план
и контракты приёмки.

Сохраняются и остальные гарантии ALK: отсутствие runtime-зависимостей,
отсутствие провайдерского запуска в ядре, отсутствие кэша решений о доверии и
неослабленные проверки свежести, редакции, подписей и ресурсов.

См. [Review Mesh](review-mesh.md) и [публичные контракты](public-contracts.md).
