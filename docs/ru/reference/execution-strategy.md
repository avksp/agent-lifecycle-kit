# Стратегия выполнения без снижения качества

Стратегия выполнения объединяет существующие решения ALK в один ограниченный
артефакт, не зависящий от поставщика модели. Она отвечает на четыре вопроса,
не вызывая модель и не меняя состояние рабочего цикла:

1. Какой минимальный уровень качества и уровень риска обязательны?
2. Какой нейтральный класс модели подходит для каждого этапа?
3. Можно ли передать задачу в компактном пакете?
4. Какая проверка и какие сведения о расходе требуются?

Стратегия служит пояснением и передачей решения между этапами. Она не может
зафиксировать план, разрешить реализацию, запустить внешний инструмент, принять
задачу или завершить рабочий цикл.

## Простой путь

Используйте единую команду:

```bash
agent-lifecycle start --adapter codex --mode plan --file task.md
```

Обычный текст и Markdown ещё не имеют полномочий зафиксированного плана. Поэтому
`agent-lifecycle-start-receipt.v1` содержит:

```json
{
  "executionStrategy": {
    "status": "DEFERRED_UNTIL_FREEZE",
    "reason": "frozen-plan-required",
    "advisoryOnly": true
  }
}
```

После передачи проверенного зафиксированного запуска в
`start --mode implement` это поле становится кратким резюме, привязанным к
точному плану, задаче, операции, ревизии состояния, адаптеру и исходной
ревизии. Выполнение по-прежнему разрешают отдельные контрольные точки плана и
задачи.

## Полный артефакт стратегии

Опытный пользователь может записать полный
`agent-execution-strategy.v1`:

```bash
agent-lifecycle strategy resolve \
  --manifest tasks/my-release/plan.manifest.json \
  --lock tasks/my-release/plan.lock.json \
  --state work/my-release/run.state.json \
  --task WS-01 \
  --operation-id strategy-WS-01 \
  --expected-revision 3 \
  --source-revision "$(git rev-parse HEAD)" \
  --adapter codex \
  --host-model-profile profiles/hosts/codex-live-profile.v1.json \
  --out work/my-release/WS-01/execution-strategy.json
```

Выходной файл создаётся один раз и не перезаписывается. Для S1 и S2 нужен
локальный профиль моделей хоста: он подтверждает, что установленный инструмент
поддерживает нейтральный класс модели. Конкретные названия поставщика и модели
остаются в локальном профиле и не попадают в переносимую стратегию.

Артефакт содержит:

- точное происхождение и отпечатки исходных решений;
- уровень риска, нижнюю границу качества и выбранный режим;
- маршруты детерминированных проверок, реализации и аудита;
- полный или компактный вид пакета;
- рекомендацию дополнительной групповой проверки либо причину её пропуска;
- пределы токенов, обращений и времени;
- требуемую достоверность данных о расходе;
- явный запрет на полномочия и побочные действия.

## Передача в пакет задачи

Передайте проверенную стратегию обычному компилятору:

```bash
agent-lifecycle task compile \
  --manifest tasks/my-release/plan.manifest.json \
  --strategy work/my-release/WS-01/execution-strategy.json \
  --write
```

Краткая проекция попадёт только в пакет связанной задачи. Отпечаток плана,
разрешённые пути записи, критерии приёмки, проверки и полномочия результата
по-прежнему берутся из зафиксированного плана.

Для подходящей задачи с низким риском:

```bash
agent-lifecycle task compile-small \
  --manifest tasks/my-release/plan.manifest.json \
  --strategy work/my-release/WS-01/execution-strategy.json \
  --context-profile profiles/small-context-profile.v1.json \
  --target-window 4k-strict \
  --write
```

Строгий, релизный и защищённый S2-маршрут блокирует компактный пакет. В таком
случае используйте полный пакет либо разделите задачу и повторно зафиксируйте
план. Понижать уровень риска нельзя.

## Большие и локальные модели

ALK выбирает класс возможностей, а не название продукта:

| Вид работы | Безопасный вариант |
| --- | --- |
| Проверка схем и релизных правил | Без модели. |
| Ограниченная задача S0 с компактным контрактом | Небольшая или локальная модель и компактный пакет. |
| Реализация S1 | Стандартный класс для программирования с подтверждением расхода. |
| Реализация S2, архитектура или безопасность | Полный пакет и класс с усиленным рассуждением. |
| Независимый аудит реализации или завершения | Класс, пригодный для проверки; несколько проверяющих только по требованию плана. |

Большая модель не обходит контрольные точки. Небольшая модель получает меньше
контекста только тогда, когда все полномочия и условия можно сохранить без
сокращения требований.

## Проверка оптимизации

Сначала оцените исходный и новый варианты, затем сравните их артефакты:

```bash
agent-lifecycle benchmark compare \
  --baseline work/benchmark/baseline-evaluation.json \
  --candidate work/benchmark/candidate-evaluation.json \
  --out work/benchmark/comparison.json
```

Сначала проверяется качество, затем экономия. Новая ложная приёмка, потерянная
проверка эталона или несовпадение происхождения приводят к отказу. Оценочные
токены дают только рекомендацию. Пригодность для автоматического принятия
требует одновременно:

- сопоставимых данных о токенах, подтверждённых хостом;
- фактического снижения расхода токенов;
- отсутствия роста обращений, повторов, циклов исправления и времени;
- отсутствия пробелов в измерениях.

Артефакт не меняет правила автоматически. Он служит подтверждением для
последующей проверенной правки плана или политики.

## Архитектурная граница

`policy/execution_strategy.py` объединяет существующие решения по нижней
границе качества, риску, адаптивному режиму, классу модели, дополнительной
проверке и компактным пакетам. Нижележащие модули не зависят от слоя стратегии.
В ядре нет API поставщиков, запуска процессов и скрытого кеша проверок.
