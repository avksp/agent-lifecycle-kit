# Запуск адаптера только для планирования

ALK принимает текст задачи или Markdown через единую команду. Если профиль
адаптера для точной версии прошёл квалификацию, команда может запустить один
внешний CLI в режиме только для планирования:

```bash
agent-lifecycle start \
  --adapter codex \
  --mode plan \
  --file task.md \
  --launch
```

Без `--launch` та же команда только создаёт локальный черновик и не запускает
внешний процесс. Обычный текст в режиме `--mode implement` всегда отклоняется.

## Текущее состояние поддержки

Запуск для планирования не следует смешивать со зрелостью адаптера и с
квалифицированным запуском уже зафиксированной задачи реализации.

| Адаптер | Точная версия-кандидат | Состояние запуска для планирования |
| --- | --- | --- |
| Codex | `0.147.0` | `PLANNING_ONLY_UNSUPPORTED` до успешного подтверждения ограничений в реальном запуске |
| Claude Code | `2.1.226` | `PLANNING_ONLY_UNSUPPORTED` до успешного подтверждения ограничений в реальном запуске |
| OpenCode | `1.18.15` | `PLANNING_ONLY_UNSUPPORTED` до появления безопасного профиля и подтверждения реальным запуском |
| Cursor, Gemini CLI, Goose, Grok Build, Hermes, Kimi Code, OpenInterpreter, Pi, Qwen Code | В этом контракте не объявлена | Запуск для планирования не поддерживается |

Зрелость `VERIFIED` и состояние управляемой сессии `WRAPPER_ONLY` не повышают
этот статус. Проверка структуры профиля или версии команды также недостаточна.
Пока профиль не содержит подтверждение `PLANNING_ONLY_QUALIFIED` для точной
версии, `--launch` завершается безопасным отказом.

## Подготовка и проверка кандидата

Для Codex, Claude Code и OpenCode доступны генераторы профиля-кандидата:

```bash
agent-lifecycle adapter launch-profile \
  --adapter codex \
  --repository-root /path/to/agent-lifecycle-kit \
  --out .alk/host-launch/codex.json

agent-lifecycle host-launch inspect \
  --profile .alk/host-launch/codex.json

agent-lifecycle host-launch preflight \
  --profile .alk/host-launch/codex.json
```

При необходимости замените `codex` на `claude` или `opencode`. Профиль и
подтверждение проверки версии хранятся в исключённом из Git каталоге
`.alk/host-launch/`. Предварительная проверка не вызывает модель. Она
необходима, но сама по себе не подтверждает безопасность планирования.

Если профиль по умолчанию отсутствует, `start --launch` возвращает в блокере
точные команды подготовки и проверки. ALK не создаёт и не принимает профиль
неявно.

## Граница безопасности и жизненного цикла

Квалифицированный маршрут планирования:

- передаёт ограниченный объём текста через стандартный ввод, а не аргументы;
- использует точный список переменных окружения и `shell=False`;
- разрешает не более одного ограниченного по времени процесса;
- требует встроенные ограничения внешнего CLI на запись и инструменты;
- сравнивает состояние Git до и после запуска;
- хранит только отпечатки задачи и результата в
  `agent-planning-session-state.v1` внутри `.alk/planning-sessions`;
- возвращает `REVIEW_REQUIRED` или `BLOCKED` и
  `implementationAuthorized: false`.

Внешнее подтверждение `agent-lifecycle-start-receipt.v1` сохраняет стабильное
действие `DRAFT_PLAN_REVIEW` и признак отсутствия вызова модели на уровне
фасада. Вложенное подтверждение `agent-planning-launch-receipt.v1` отдельно
фиксирует фактический запуск процесса и модели в поле `modelCallsStarted`.

Текст задачи и ответ внешнего инструмента считаются недоверенными данными. Они
не могут одобрить инструменты, зафиксировать план, разрешить реализацию или
заменить независимую проверку. При изменении рабочего дерева ALK не удаляет и
не откатывает изменения пользователя.

## Возобновление и переход к реализации

Подтверждение содержит идентификатор сессии планирования ALK. Возобновление
читает только состояние с отпечатками и не подключается к диалогу внешнего CLI:

```bash
agent-lifecycle start --adapter codex --resume <planning-session-id>
```

Успешное планирование завершается на проверке. Для реализации нужны отдельно
проверенный манифест `FROZEN`, совпадающий lock-файл, пакет задачи, профиль
риска и новый квалифицированный процесс `managedTask`. Этот отдельный маршрут
описан в разделе [квалифицированный запуск внешнего
инструмента](qualified-host-launch.md), а атомарные команды сессий приведены в
разделе [управляемые сессии адаптеров](managed-adapter-sessions.md).
