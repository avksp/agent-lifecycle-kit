# Необязательный мост управления тредами

Мост управления тредами позволяет адаптеру передавать принадлежащие хосту
треды и другие сущности оболочки через типизированные артефакты ALK. Это
граница обмена для операций `read`, `list`, `send` и `create`, а не второй
контроллер жизненного цикла.

## Как работает мост

Обмен состоит из четырёх явных шагов:

1. ALK подготавливает ограниченный запрос
   `agent-thread-operation-request.v1`.
2. Адаптер проверяет объявленные возможности и выполняет операцию хоста,
   если для неё есть подтверждённая поддержка.
3. Адаптер возвращает
   `agent-thread-operation-receipt.v1` со связью с запросом, статусом и
   сведениями об очистке данных.
4. ALK проверяет обмен и может импортировать результат как
   `agent-thread-context-import.v1`.

Для создания этих артефактов ядру не нужны SDK провайдера, сетевой клиент или
процесс хоста. Идентификаторы нативных тредов и способ передачи остаются в
адаптере. Объявление возможности описывает поддержку, а отдельная квитанция
квалификации адаптера подтверждает её пригодность к работе.

## Операции и подтверждения

| Операция | Назначение | Область | Подтверждение | Условие квитанции |
| --- | --- | --- | --- | --- |
| `read` | Прочитать выбранный тред | Явная цель | Не требуется | Связь запроса и ответа |
| `list` | Получить ограниченный список сущностей | Проект или рабочий процесс | Не требуется | Ограниченный результат и связь |
| `send` | Отправить сообщение в выбранный тред | Явная цель | Оператор | Подтверждение и ключ идемпотентности |
| `create` | Создать сущность проекта или процесса | Проект или рабочий процесс | Оператор | Подтверждение и ключ идемпотентности |

В профиле проекта используется единая политика `threadBridge`. По умолчанию она
выключена и включается отдельно для каждой операции и этапа. Зафиксированный
план может потребовать операцию или сузить её область и лимиты. Эффективный
профиль применяет границы плана после проверки профиля.

## Подготовка запроса

Подготовьте запрос на чтение конкретного треда:

```bash
agent-lifecycle thread request \
  --operation read \
  --target-hash <хеш-ссылки-на-тред> \
  --max-tokens 2048 \
  --out work/thread/read-request.json
```

Подготовьте ограниченный список сущностей проекта:

```bash
agent-lifecycle thread request \
  --operation list \
  --scope project \
  --max-tokens 1024 \
  --out work/thread/list-request.json
```

Изменяющие операции требуют подтверждения оператора и ключа идемпотентности:

```bash
agent-lifecycle thread request \
  --operation send \
  --target-hash <хеш-ссылки-на-тред> \
  --text "Проверьте приложенный план" \
  --idempotency-key send-plan-001 \
  --out work/thread/send-request.json
```

Команда только подготавливает JSON. Адаптер читает запрос, выполняет действие
на стороне хоста и создаёт квитанцию в своей границе интеграции.

## Импорт квитанции

Импортируйте ответ адаптера как дополнительный контекст:

```bash
agent-lifecycle thread import \
  --request work/thread/read-request.json \
  --receipt work/thread/read-receipt.json \
  --source-id selected-thread \
  --out work/thread/context.json
```

Импортированный артефакт содержит отпечаток источника, состояние очистки данных
и ограничения ресурсов. Его можно использовать для восстановления контекста или
подготовки пакета проверяющего. Он не является спецификацией, планом,
подтверждением приёмки или финальным доказательством.
В квитанции такой контекст помечается как `sourceOfTruth: false` и
`proof: false`.

## Связь с Review Mesh и снимками контекста

Тредовый контекст можно добавить к поиску по эпизодам или передать в пакет
Review Mesh с ролью `optional-thread-context`. Review Mesh по-прежнему отвечает
за назначения проверяющим, импорт результатов, объединение выводов и кворум;
операции тредов только передают выбранный контекст.

Для продолжительной работы ALK основным артефактом непрерывности остаётся
снимок контекста. Импорт треда может войти в такой снимок, но не меняет его
связь с планом и не выдаёт право на реализацию. См. страницы [снимков
контекста](context-checkpoints.md) и [проверки несколькими моделями ИИ](review-mesh.md).

## Пример политики проекта

```json
{
  "threadBridge": {
    "mode": "read-only",
    "operations": {
      "read": {"enabled": true, "scope": "explicit-target", "approval": "none", "blocking": "required"},
      "list": {"enabled": true, "scope": "project", "approval": "none", "blocking": "non-blocking"},
      "send": {"enabled": false, "scope": "explicit-target", "approval": "operator", "blocking": "required"},
      "create": {"enabled": false, "scope": "project", "approval": "operator", "blocking": "required"}
    },
    "phaseRules": {"research": {"read": {"enabled": true, "scope": "explicit-target"}}},
    "limits": {"maxImportedBytes": 32768, "maxImportedTokens": 2048}
  }
}
```

Мост необязателен. Проект без `threadBridge` продолжает использовать обычный
жизненный цикл ALK.
