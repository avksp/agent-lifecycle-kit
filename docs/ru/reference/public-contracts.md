# Публичные контракты

Публичные контракты — это стабильные схемы JSON, которыми связаны CLI,
документация, тесты и проверочные артефакты.

## Основные контракты

- `completionCheck`: обязательная проверка завершения на уровне задачи.
- `agent-completion-check-receipt.v1`: подтверждение завершения.
- `agent-completion-gate-receipt.v1`: решение stop/continue/escalate/split/follow-up.
- `agent-completion-gate-validation.v1`: проверка артефакта завершения.
- `agent-goal-record.v1`: запись цели.
- `agent-objective-snapshot.v1`: компактный снимок цели.
- `agent-runner-state.v1`: состояние управляемого выполнения.
- `agent-runner-snapshot.v1`: компактный снимок состояния запуска.
- `agent-follow-up-register.v1`: реестр продолжений.
- `agent-follow-up-summary.v1`: краткое состояние продолжений.
- `agent-worktree-isolation-policy.v1`: политика изоляции рабочего дерева.
- `agent-worktree-attempt-receipt.v1`: подтверждение изоляции рабочего дерева.
- `agent-worktree-writeback-receipt.v1`: решение применить или отклонить
  наложение изменений.
- `agent-adapter-event-stream-receipt.v1`: поток событий адаптера.
- `agent-adapter-event-capture-validation.v1`: проверка подтверждений захвата
  событий.
- `agent-review-verdict.v1`: проверочный вердикт.
- `agent-review-routing-summary.v1`: резюме маршрутизации для проверки.
- `agent-optional-quality-pack.v1`: явно включаемый пакет качества.
- `agent-behavior-check-run.v1`: результат проверки поведения.
- `agent-task-template-library.v1`: каталог черновых шаблонов задач.
- `agent-task-template-library-validation.v1`: проверка шаблонов задач.
- `agent-task-template-render.v1`: результат подготовки одного шаблона задачи.
- `agent-bug-forensics-recipe-library.v1`: каталог рецептов Bug Forensics.
- `agent-bug-forensics-recipe-validation.v1`: проверка рецептов Bug Forensics.
- `agent-diagnostic-bundle.v1`: диагностический пакет.
- `agent-readonly-status-view.v1`: представление статуса без записи.
- `agent-workflow-event-feed.v1`: лента событий без записи по состоянию
  рабочего цикла.
- `agent-lifecycle-progress-view.v1`: представление прогресса жизненного цикла
  без записи.
- `agent-proof-finding.v1`: стабильная идентичность finding.
- `agent-root-cause-evidence.v1`: подтверждение основной причины.
- `agent-fix-impact-receipt.v1`: канонический артефакт влияния исправления.
- `agent-failure-classification-receipt.v1`: нейтральный класс ошибки.
- `agent-failure-classification-validation.v1`: проверка артефакта
  классификации.
- `agent-receipt-hash-chain.v1`: цепочка артефактов, добавляемая только в
  конец.
- `agent-proof-integrity-receipt.v1`: общий артефакт целостности
  подтверждений.
- `agent-sandbox-receipt.v1`: подтверждение ограничений среды выполнения для
  файловой системы, сети, процессов, окружения и источника enforcement.
- `agent-sandbox-requirement.v1`: политика обязательного подтверждения
  песочницы, которая падает закрыто для рискованных задач.
- `agent-sandbox-capability.v1`: декларация возможностей песочницы адаптера.
- `agent-adapter-probe-profile.v1`: профиль проверки возможностей адаптера.
- `agent-adapter-probe-plan.v1`: декларативный план проб адаптера.
- `agent-adapter-probe-evidence-validation.v1`: проверка подтверждений пробы и
  расхождений.
- `agent-adapter-package-discovery.v1`: рекомендательный осмотр дерева
  исходников.
- `agent-import-dialect-profile.v1`: профиль импорта внешнего формата.
- `agent-episode-index.v1`: пересобираемый индекс эпизодов по артефактам и
  сессиям.
- `agent-episode-retrieval.v1`: ограниченный результат поиска с происхождением
  отпечатка.
- `agent-runner-attempt-snapshot-receipt.v1`: артефакт снимка, восстановления,
  отказа от попытки и метаданных выбранной попытки.
- `agent-worker-lease-receipt.v1`: артефакт закрепления исполнителя и сигнала
  активности.
- `agent-phase-resource-measurement.v1`: токены и ресурсы по фазам через
  экспорт использования без обязательного `USD-cost`.
- `agent-cross-check-profile.v1`: дополнительный профиль перепроверки,
  выключенный по умолчанию и ограниченный токенами и ресурсами.
- `agent-cross-check-receipt.v1`: артефакт дополнительной проверки.
- `agent-runtime-policy-receipt.v1`: артефакт решения по правилам запуска.
- `agent-lifecycle-quality-floor-decision.v1`: минимальный безопасный режим.
- `agent-adaptive-lifecycle-policy-request.v1`: нейтральный вход адаптивной
  политики.
- `agent-adaptive-lifecycle-policy-decision.v1`: решение адаптивного жизненного
  цикла.
- `agent-adaptive-lifecycle-policy-decision-validation.v1`: проверка решения.
- `agent-small-model-task-packet.v1`: пакет выполнения для маленькой модели.
- `agent-small-model-task-packet-index.v1`: индекс пакетов для маленьких
  моделей.
- `agent-small-model-output-contract.v1`: обязательный контракт результата.
- `agent-small-model-task-result.v1`: результат исполнителя по контракту
  результата.
- `agent-small-model-output-validation.v1`: проверка результата, которая падает
  при недостатке обязательных данных.
- `agent-small-model-packet-compile-result.v1`: результат компиляции CLI.
- `agent-task-outcome-index.v1`: локальный индекс исходов задач из артефактов.
- `agent-quality-cost-signals.v1`: рекомендательные сигналы качества и
  расхода.
- `agent-quality-cost-signals-summary.v1`: компактное резюме обучающих
  сигналов.
- `agent-bug-forensics-profile.v1`: дополнительный профиль для исправления
  багов и регрессий.
- `agent-bug-reproduction-receipt.v1`: подтверждение воспроизведения до
  изменения.
- `agent-failure-fingerprint.v1`: стабильный отпечаток ошибки.
- `agent-bug-hypothesis-ledger.v1`: принятые и отвергнутые гипотезы и проверка
  минимальности правки.
- `agent-regression-proof-receipt.v1`: тот же отпечаток красный до правки и
  зелёный после.
- `agent-bug-forensics-gate-receipt.v1`: артефакт проверки рабочего цикла.
- `agent-bug-forensics-audit.v1`: резюме аудита для проверки bug-forensics.
- `agent-lifecycle-policy-proposal.v1`: предложение по настройке правил.

## Правило совместимости

Новые схемы должны добавляться явно и проходить `agent-lifecycle contract
check`. Изменение контракта без тестов и документации считается небезопасным.

`agent-fix-impact-receipt.v1` — основной контракт для фиксации влияния
исправления. Он связывает изменённые файлы, `findingId`, отпечаток основной
причины, изменённые и сохранённые поведенческие контракты, регрессионные
подтверждения и проверку побочного влияния.

`agent-failure-classification-receipt.v1` классифицирует сбой как крайний
случай, контракт API, гонку, нестабильный тест, дефект безопасности или
`unknown`. Артефакт фиксирует уверенность, найденные подтверждения и
происхождение отпечатка без имён провайдеров и моделей в ядре.

`agent-sandbox-receipt.v1` не заменяет
`agent-worktree-attempt-receipt.v1`. Артефакт рабочего дерева ограничивает пути
записи в репозитории, а артефакт песочницы описывает ограничения среды
выполнения. `UNKNOWN` — валидное явное состояние возможности, но обязательная
политика для рискованных задач принимает только настроенные проходящие статусы,
по умолчанию `PASS`. Частичное ограничение и границы прокси для учётных данных
остаются деталями внутри `agent-sandbox-receipt.v1`; отдельный псевдоним схемы
для execution-sandbox не вводится.

План проб адаптера является детектором расхождений для реальной проверки
совместимости на этапе релиза. Он не запускает реальные вызовы, не меняет
зрелость и не заявляет промышленную готовность.

`agent-import-dialect-profile.v1` требует `sourceTrusted: false`,
`requiresReview: true` и `freezeBlocked: true`. `nativeDialectProfileDigest`
фиксирует происхождение импортированного формата, но не означает одобрение.

Общий внешний импорт workflow и agent/harness использует тот же
`agent-import-dialect-profile.v1` с метаданными семейства и профиля. Импорт
семейства workflow создаёт проверяемые требования и подсказки для валидации без
выполнения импортированных узлов. Импорт семейства agent хранит подсказки
`provider`, `model`, `auth`, `environment` и `tool` как замаскированные
локальные метаданные хоста; это не переносимые настройки по умолчанию.

`agent-episode-retrieval.v1` возвращает ограниченную проекцию контекста по явно
переданным артефактам и сессиям. Результат получает `chainVerified` только
при совпадении пути и отпечатка с записью в цепочке хэшей; иначе состояние остаётся
`chainUnchecked`.

Артефакты восстановления запуска добавляют подтверждения для нескольких
попыток, но не заменяют состояние рабочего цикла. Профиль перепроверки остаётся
рекомендательным и включается явно, пока план не требует обязательной
перепроверки. Независимость проверяется по
нейтральным `hostIdentityHash` и `modelIdentityHash`, а не по именам
провайдеров.

`agent-runtime-policy-receipt.v1` отделяет доказанное принудительное ограничение
до выполнения от рекомендательного журналирования после факта.
`agent-worktree-writeback-receipt.v1` фиксирует применение или отклонение
наложения изменений и не заменяет `agent-sandbox-receipt.v1`.

Адаптивная политика жизненного цикла выбирает самый лёгкий безопасный режим по
нейтральным входам задачи, риска, подтверждений и ресурсов. По умолчанию это
рекомендательное решение; автоматический выбор требует явного включения и не
может быть ниже `quality floor`. Имена провайдера и модели, а также поиск
валютных данных для реального режима не используются в переносимом ядре.

Quality-cost learning строит локальные рекомендательные сигналы из явных
артефактов жизненного цикла. Он группирует исходы по форме задачи, режиму
жизненного цикла, классу маршрута и профилю, учитывает токены, время
выполнения, вызовы инструментов, повторы и долю блокеров, но не запускает
телеметрию, не требует полей стоимости в USD, не строит provider/model leaderboards
и не меняет политику автоматически.

Пакеты для маленьких моделей сужают поверхность реализации: точные границы
записи, компактный артефакт контекста и обязательный контракт результата. Они
не расширяют полномочия и сами по себе не закрывают критическую проверку.

Bug Forensics включается только явным маркером задачи или профиля. Для влияния
правки он использует существующий `agent-fix-impact-receipt.v1`, а для
рискованной перепроверки — `agent-cross-check-receipt.v1` с ограничениями
токенов и ресурсов без обязательного `USD-cost`.

Рецепты Bug Forensics являются метаданными над существующей цепочкой
артефактов. Они дополнительны, выключены по умолчанию и не могут вводить
конкурирующие схемы артефактов для исправления дефектов.

Лента событий и представление прогресса жизненного цикла являются только
проекциями. Они не запускают модельные вызовы, не тратят токены и не меняют
состояние рабочего цикла.
