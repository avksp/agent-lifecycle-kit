# Квалификация структурированного результата

В релизе 1.89 появился нейтральный к провайдеру контракт для проверки того,
может ли вариант выполнения выдавать структурированные результаты для одной
операции ALK. Это необязательная поверхность квалификации. Она не заменяет
зафиксированный план, приёмку task-result, аудит реализации и финальное
доказательство рабочего процесса.

## Capability привязан к операции

ALK записывает заявление о capability только для проверяемой операции. Оно
связано со всеми следующими значениями:

- идентификатор операции;
- идентификатор адаптера и digest его дескриптора;
- версия хоста и класс модели;
- digest capability-manifest;
- требуемая схема результата;
- линия происхождения плана и lock.

Публичный контракт — `agent-structured-result-capability.v1`. Изменённая,
отсутствующая, устаревшая или повторно использованная привязка даёт
`UNAVAILABLE` или `FAIL`. Она никогда не повышает более слабое наблюдение до
более сильного уровня. Уровни: `SCHEMA_ENFORCED`, `JSON_ENFORCED`,
`VALIDATED_TEXT` и `UNAVAILABLE`.

Заявление capability является подтверждением свойств маршрута, а не правом на
его использование. Оно не может принять задачу рабочего процесса,
авторизовать действие, изменить security-гейт или заявить о промышленной
готовности.

## Выбор без незаметного понижения

Контракт выбора — `agent-structured-result-selection.v1`. ALK выбирает самый
сильный квалифицированный режим, который удовлетворяет требуемой схеме, и
записывает требуемую схему вместе с линией происхождения plan/lock. Если
требуется принудительная схема, а она недоступна, выбор завершается отказом.
Переход на более слабый режим только ради получения результата запрещён.

Граница выбора отделена от команды хоста. Адаптер может предоставить
capability-manifest, но ALK сначала проверяет его происхождение относительно
дескриптора адаптера и только потом использует заявление как подтверждение.

## Детерминированная проверка и ограниченный ремонт

`agent-structured-result-validation.v1` описывает детерминированную проверку
возвращённого конверта. Отклоняются повреждённый JSON, обязательные поля,
неверная схема, устаревшая линия происхождения и повторно использованный
receipt. Для ремонта структурированного результата разрешены максимум две
попытки. Попытки задачи жизненного цикла — отдельный бюджет, заданный
зафиксированным `maxTaskAttempts`; ремонт результата его не увеличивает.

Исчерпанный бюджет ремонта не может стать принятым подтверждением. Ремонт не
может изменить требуемую схему, критерии качества, security-гейты или линию
происхождения плана.

## Подтверждения квалификации

Отчёт квалификации использует существующую модель подтверждений по эталонным
задачам. До рекомендации маршруту нужно иметь всё перечисленное:

- минимум пять разных эталонных задач;
- два завершённых запуска для каждой задачи;
- минимум пять разных страт `family/tier/shape`;
- два завершённых запуска для каждой страты;
- положительные, граничные и повреждённые фикстуры результата;
- полную линию происхождения и измерения structured result для каждого запуска.

Недостаток подтверждений или провал отрицательной фикстуры дают
`NO_RECOMMENDATION`. Один успешный запуск недостаточен. Отчёт остаётся
рекомендательным и содержит `automaticRouteAdoptionEligible: false` и
`advisoryOnly: true`; он не может принять задачу или изменить уровень
поддержки адаптера.

Для встроенного детерминированного набора можно использовать обычные команды
benchmark:

```bash
agent-lifecycle benchmark qualify \
  --suite benchmarks/reference-tasks/manifest.json \
  --sample work/benchmark/sample.json \
  --receipt work/benchmark/run-01.json \
  --receipt work/benchmark/run-02.json \
  --out work/benchmark/qualification.json
```

Команда читает внешние записи выполнения. Она не запускает модель или процесс
хоста. Помощники и receipt структурированной квалификации доступны также
через Python API; в 1.89 намеренно не добавлена провайдерская CLI-опция для
формата ответа.

## Границы контракта и полномочий

Используются следующие схемы:

- `agent-structured-result-capability.v1`;
- `agent-structured-result-selection.v1`;
- `agent-structured-result-output-contract.v1`;
- `agent-structured-result-validation.v1`;
- `agent-structured-result-measurement.v1`;
- `agent-workflow-structured-result-artifact.v1`.

Общий output contract используется также компилятором пакетов для маленьких
моделей. Это не второй источник полномочий компилятора и не второй движок
рабочего процесса. Артефакт структурированного результата остаётся
рекомендательным, пока обычные проверки ALK task-result, владения, свежести,
ревью и финализации не примут работу.

Поэтому уровень capability полезен для сравнения и диагностики, а
зафиксированный план и состояние жизненного цикла остаются источником
полномочий.
