# Поддержка платформ в учёте расходов

Release 2.16 отделяет гарантии файловых операций ALK от возможностей выбранного
хоста. Успешная проверка хранилища или канала не подтверждает поддержку модельного
хоста, полноту его расходов или право защищённого финансового закрытия.

| Граница | POSIX | Windows / NTFS |
| --- | --- | --- |
| Приватные данные | Реальный владелец, права и защищённый путь | Реальный SID токена, владелец/DACL и удерживаемый путь |
| Чтение входов | Удерживаемые каталоги, обычные файлы и лимит чтения | Удерживаемые Win32-дескрипторы, отказ для reparse и лимит чтения |
| Надёжная запись координатора | Проверяемые файловые и каталожные барьеры | Проверяемые файловые барьеры и `FlushFileBuffers` каталога |
| Локальные байтовые каналы | Существующая готовность дескрипторов | Неблокирующие анонимные каналы с конечным ожиданием |

В Windows приватность определяется фактическими ACL. Небезопасные существующие
права приводят к отказу; mode bits не выдаются за права POSIX. Проверки личности
каталога, типа файла и жёстких ссылок сохраняются. Существующее исключение для
диагностики позволяет вернуть только исходный readonly-флаг неизменённого
`installation_id`. Оно не исправляет небезопасный DACL и не допускает подмену
файла, содержимого или политики доступа.

Квитанция ввода показывает байты, принятые каналом ОС. Она не доказывает их
потребление хостом. Сроки, отмена, ограничения вывода и очистка процесса остаются
обязанностями вызывающей стороны. Тестовый процесс Python и проверка ядра ОС
не подтверждают пригодность native-запуска Codex.

Накопительный журнал сохраняет расходы задачи и запуска, повторы, проверки,
аудиторов и работу координатора в пределах допущенной границы учёта. Отсутствующие
метрики хоста остаются недоступными (`null`), а не нулевыми. Для текущего Codex
ограниченный учёт входа ALK не устанавливает лимит на все модельные вызовы хоста.
Каждому маршруту нужны собственные документированные возможности и подтверждение
пригодности. Неподдерживаемое защищённое закрытие возвращает
`UNSUPPORTED_OPERATOR_ROUTE`.

Сырые подробности удаляются через 30 дней после полного закрытия запуска штатной
ALK-командой обслуживания по расписанию. Незавершённые запуски сохраняют свои
обязательства. Итоги, идентификаторы защиты от повторного списания, удержания
и исходные сроки переживают очистку и compact; файловая проверка их не снимает.

В исходном репозитории на Windows/NTFS новую квитанцию можно получить командой:

```text
python -B tools/release/validate_windows_primitives.py --repository-root . --evidence work/windows-primitives.json
```

Команда не перезаписывает старый результат. Квитанция содержит фактическую среду,
файловую систему, проверки ядра и хеши исходников до и после. POSIX-запуск не может
дать Windows PASS. Результат ARM64/SYSTEM VM описывает только эту среду. Приёмка
релиза дополнительно требует CI-матрицу текущих исходников и независимую проверку;
старые квитанции хоста сохраняют исходную привязку к версии, режиму и исходникам.
