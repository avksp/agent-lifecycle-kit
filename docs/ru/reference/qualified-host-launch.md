# Квалифицированный запуск зафиксированной задачи

ALK описывает квалифицированный запуск зафиксированной задачи для трёх внешних
командных инструментов с точной привязкой к версии. Это дополнительный способ
запуска уже зафиксированной задачи, а не посредник поставщиков моделей и не
заявление о прямом запуске любого адаптера.

Раздел описывает реализацию уже проверенной и зафиксированной задачи. Он не
квалифицирует планирование по обычному тексту. Этот отдельный контракт описан в
разделе [запуск адаптера только для планирования](planning-only-launch.md).

| Адаптер | Проверенная версия | Исполняемый файл |
| --- | --- | --- |
| [Codex](../adapters/codex.md) | `0.147.0` | `codex` |
| [Claude Code](../adapters/claude.md) | `2.1.226` | `claude` |
| [OpenCode](../adapters/opencode.md) | `1.18.15` | `opencode` |

В дескрипторах адаптеров сохраняется
`managedLaunch.status: WRAPPER_ONLY`. Подтверждение относится только к точному
локальному профилю и установленной версии.

## Почему в основной таблице три адаптера

У всех двенадцати встроенных адаптеров есть локальное описание точной версии.
Поэтому для каждого можно создать профиль, проверить его структуру и выполнить
ограниченную проверку версии. Это более широкая возможность, чем
квалифицированный запуск зафиксированной задачи.

Для трёх адаптеров из основной таблицы также предусмотрены специальные профили
продолжения зафиксированной задачи, испытательные обвязки и нормализаторы
расхода этого маршрута. Описания остальных девяти адаптеров нужны для явной
проверки будущего запуска планирования и безопасного отказа. Они не заявляют
публичную поддержку управляемого запуска задачи:

Для каждой строки значения `qualifiedLaunch.publicSupportClaimed` и
`productionPromotionClaimed` остаются `false`. Успешная проверка `--version`
подтверждает только соответствие профиля и версии. Эти девять профилей нельзя
считать принятым доказательством реализации, пока отдельная проверка адаптера
явно не повысит состояние такого маршрута.

## Создание локального профиля

Выполните команду в целевом проекте. В `--repository-root` укажите исходный
каталог или каталог подключаемого модуля ALK, где находится профиль адаптера:

```bash
agent-lifecycle adapter launch-profile \
  --adapter codex \
  --repository-root /path/to/agent-lifecycle-kit \
  --out .alk/host-launch/codex.json
```

Для другого документированного маршрута зафиксированной задачи замените
`codex` на `claude` или `opencode`. Команда создания профиля принимает и
идентификаторы остальных встроенных адаптеров, но для них действует граница из
таблицы выше. Результат разрешено сохранять только как
`.alk/host-launch/<имя>.json`. Абсолютные и вложенные пути, выход из каталога и
символические ссылки отклоняются.

## Проверка установленной команды

Проверка структуры не создаёт процесс:

```bash
agent-lifecycle host-launch inspect \
  --profile .alk/host-launch/codex.json
```

Проверка готовности запускает один ограниченный процесс с `--version` и
создаёт рядом с профилем подтверждение, связанное отпечатком:

```bash
agent-lifecycle host-launch preflight \
  --profile .alk/host-launch/codex.json
```

Схема подтверждения: `agent-host-launch-qualification-receipt.v1`.

В подтверждении должны совпасть адаптер, отпечаток профиля, ожидаемая и
фактическая версии. Отсутствующее подтверждение, изменение профиля или версии,
превышение времени и ненулевой код завершения блокируют основной запуск до
создания процесса.

## Запуск зафиксированной задачи

Используйте профиль только с полным зафиксированным запросом режима
`implement`:

```bash
agent-lifecycle start \
  --adapter codex \
  --mode implement \
  --file work/run/adapter-run-request.json \
  --risk auto \
  --host-model-profile profiles/hosts/codex-live-profile.v1.json \
  --launch \
  --host-launch-profile .alk/host-launch/codex.json
```

В поставляемых аргументах нет исходного текста задачи и флагов автоматического
одобрения. Внешний инструмент получает указание продолжить уже зафиксированную
задачу ALK в текущем проекте. Перед созданием процесса ALK повторно проверяет
файл блокировки плана, происхождение задачи, операцию, исходную редакцию и
профиль риска.

## Границы учёта и поддержки

Три обработчика умеют извлекать разрешённые счётчики из ограниченного потока
JSON, но в дескрипторах пока указаны `FIXTURE_ONLY` и
`acceptedForS1S2: false`. Проверка версии не подтверждает учёт токенов модели.
Поэтому приёмка S1/S2 остаётся заблокированной до появления отдельного
подтверждения расхода от внешнего инструмента.

Профиль не выполняет вход в учётную запись, не объединяет учётные записи, не
выбирает поставщика модели, не меняет настройки внешнего инструмента, не
возобновляет его диалог и не повышает зрелость адаптера. См. [локальный запуск
внешней команды](local-host-launch.md), [использование ALK с
адаптером](../adapters/usage-modes.md), [управляемые сессии
адаптеров](managed-adapter-sessions.md) и [матрицу поддержки
адаптеров](../adapters/support-matrix.md).
