# Независимость подтверждений

ALK различает обычные и статистические подтверждения. Обычные task receipts
сохраняют прежний маршрут. Статистическое заявление или оценка частоты ошибок
дополнительно указывает происхождение каждого примера, способ получения и
основание независимости от проверяемой реализации.

## Контракты

Общий маршрут независимости использует:

- `agent-independence-requirement.v1`;
- `agent-independent-evidence.v1`;
- `agent-independent-evidence-validation.v1`.

Статистический маршрут использует:

- `agent-statistical-evidence-requirement.v1`;
- `agent-statistical-evidence-set.v1`;
- `agent-statistical-evidence-validation.v1`.

Метод `statistical-check` дополняет существующие `deterministic-check` и
`human-review`. Он не делает статистическое подтверждение обязательным для
обычного нестатистического критерия acceptance.

## Обязательное происхождение

Каждый статистический пример объявляет стабильный sample identity, source
class, derivation identity, source revision, digest исходного lineage и
утверждение о независимости. Допустимые классы: `IMPLEMENTATION`,
`INDEPENDENT_HOLDOUT` и `EXTERNAL_OBSERVATION`.

В effective count входят только уникальные примеры требуемого актуального
lineage. Повтор identity, устаревшая ревизия, устаревший lineage и нераскрытый
общий producer реализации и holdout-подтверждения приводят к отказу. Сырые
данные не копируются в результат: ограниченная проекция хранит только
объявленные поля происхождения и digest.

## Достаточность

Поддерживается точная граница rule of three с доверительным уровнем 95%.
Минимальное effective independent sample count выводится из заявленного порога
ошибки:

- для 2% нужно минимум 150 примеров; 149 не проходит;
- для 1% нужно минимум 300 примеров; 299 не проходит.

Валидатор использует точную десятичную арифметику и ограничение 10 000
примеров. Превышение лимита, неизвестный метод или повреждённое требование дают
стабильный отказ, а не пропуск проверки.

## Граница полномочий

Статистическое подтверждение может удовлетворить только критерий, который явно
ссылается на его evidence ID. Оно не может одобрить план, принять задачу,
закрыть находку или заменить независимую проверку. Отсутствующее происхождение
остаётся `UNAVAILABLE` или блокером и не выводится из согласия проверяющих или
успешного exit code процесса.

См. [эффективность проверки](review-efficiency.md), [Review Mesh](review-mesh.md)
и [независимую проверку для рискованных критериев](risk-bound-independent-verification.md).
