# Публикация плагинов

Основной путь установки ALK - неизменяемый тег с семантической версией. Одного
тега в репозитории недостаточно: метаданные устанавливаемого плагина внутри
этого тега тоже должны указывать ту же версию и ссылку на исходник.

## Контракт

`agent-publication-manifest.v1` перечисляет поверхности публикации, которые
должны обновляться вместе:

- файлы версии пакета: `pyproject.toml`, `uv.lock`,
  `src/agent_lifecycle/_version.py`;
- корневые манифесты плагинов для Codex, Claude Code и Cursor;
- локальные проекции плагинов в адаптерах Codex, Claude Code и Cursor;
- манифесты маркетплейсов и их ссылки на тег исходного репозитория.

Манифесты плагинов используют `version: X.Y.Z`. Записи маркетплейса, которые
устанавливают плагин из тега репозитория, используют `source.ref: vX.Y.Z`.
Если файл маркетплейса также содержит отображаемое поле `version`, оно должно
оставаться той же семантической версией.

## Проверка

Перед принятием релизного тега выполняется команда:

```bash
python tools/release/validate_publication_versions.py \
  --target-version X.Y.Z \
  --target-ref vX.Y.Z \
  --evidence work/<release>/evidence/publication-versions.json
```

Проверка падает, если какая-либо отслеживаемая поверхность публикации осталась
на старой версии или использует неверную форму поля. Команда пишет
`agent-publication-version-validation.v1` и не заявляет промышленное
продвижение или одобрение публичного каталога.

## Плавающий канал

Значение `last` нельзя записывать в `plugin.json.version`. Если хост
поддерживает плавающий канал, он допустим только как включаемая отдельно
ссылка на исходник, указывающая на уже принятый релизный коммит.
Установленный плагин всё равно должен объявлять настоящую семантическую
версию. Если хост не разделяет эти понятия, ALK использует для него только
установку по семантическому тегу.
