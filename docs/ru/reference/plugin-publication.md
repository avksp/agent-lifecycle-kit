# Публикация плагинов

Основной путь установки ALK - неизменяемый тег с семантической версией. Одного
тега в репозитории недостаточно: метаданные устанавливаемого плагина внутри
этого тега тоже должны указывать ту же версию и ссылку на исходник.

## Контракт

`agent-publication-manifest.v1` перечисляет поверхности публикации, которые
должны обновляться вместе:

- файлы версии пакета: `pyproject.toml`, `uv.lock`,
  `src/agent_lifecycle/_version.py`;
- корневые манифесты плагинов для Codex, Claude Code и Cursor;
- локальные проекции плагинов в адаптерах Codex, Claude Code и Cursor;
- манифесты маркетплейсов и их ссылки на тег исходного репозитория.

Манифесты плагинов используют `version: X.Y.Z`. Записи маркетплейса, которые
устанавливают плагин из тега репозитория, используют `source.ref: vX.Y.Z`.
Если файл маркетплейса также содержит отображаемое поле `version`, оно должно
оставаться той же семантической версией.

В этот же релиз входит отдельный переносимый архив Agent Plugins. В нём
находятся `plugin.json` и канонический каталог `skills/`; проверка выполняется
по локально закреплённой схеме Agent Plugins 1.0.0. Архив является отдельной
проекцией: он не заменяет манифесты конкретных клиентов и не добавляет MCP-
сервер или среду выполнения жизненного цикла. Состав архива и установка через
клиент описаны на странице [переносимого пакета Agent Plugins](agent-plugins.md).

## Проверка

Перед принятием релизного тега выполняется команда:

```bash
python tools/release/validate_publication_versions.py \
  --target-version X.Y.Z \
  --target-ref vX.Y.Z \
  --evidence work/<release>/evidence/publication-versions.json
```

Проверка падает, если какая-либо отслеживаемая поверхность публикации осталась
на старой версии или использует неверную форму поля. Команда пишет
`agent-publication-version-validation.v1` и не заявляет промышленное
продвижение или одобрение публичного каталога.

Рабочий процесс релиза также собирает и проверяет переносимый архив с той же
версией. Опубликованный рабочий процесс получает имя архива из неизменяемого
релизного тега и загружает его как вложение релиза GitHub с отдельным
ограниченным полномочием.

## Обновление у пользователя

Публикация тега не меняет уже закреплённую установку хоста. В Codex нужно
заменить точную ссылку источника каталога и заново установить плагин:

```bash
codex plugin remove agent-lifecycle-kit@agent-lifecycle-kit
codex plugin marketplace remove agent-lifecycle-kit
codex plugin marketplace add https://github.com/avksp/agent-lifecycle-kit.git --ref vX.Y.Z
codex plugin add agent-lifecycle-kit@agent-lifecycle-kit
codex plugin list
```

Команда `codex plugin marketplace upgrade` сохраняет настроенную ссылку и
поэтому не заменяет старый тег семантической версии. В Claude Code используются
собственные команды обновления, а `plugin marketplace add` не принимает
`--ref`:

```bash
claude plugin marketplace update agent-lifecycle-kit
claude plugin update agent-lifecycle-kit@agent-lifecycle-kit
claude plugin list
```

После обновления перезапустите сессию хоста. Новые метаданные и навыки плагина
загрузятся при следующем запуске.

## Плавающий канал

Значение `last` нельзя записывать в `plugin.json.version`. Если хост
поддерживает плавающий канал, он допустим только как включаемая отдельно
ссылка на исходник, указывающая на уже принятый релизный коммит.
Установленный плагин всё равно должен объявлять настоящую семантическую
версию. Если хост не разделяет эти понятия, ALK использует для него только
установку по семантическому тегу.
