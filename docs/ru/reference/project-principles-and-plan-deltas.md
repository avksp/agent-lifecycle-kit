# Принципы проекта и дельты плана

Для долгой работы проекту нужны два разных вида непрерывности:

- принципы проекта описывают устойчивые настройки и ограничения;
- дельта плана показывает, что изменилось между двумя проверенными версиями
  плана.

Эти артефакты упрощают передачу работы другому человеку или агенту, но не
создают второй источник истины. Полномочия по реализации по-прежнему задают
зафиксированные манифест и lock-файл плана.

Публичные контракты имеют имена `agent-project-principles.v1`,
`agent-project-principles-validation.v1`, `agent-plan-delta.v1` и
`agent-plan-delta-validation.v1`.

## Принципы проекта

Принципы хранятся в небольшом JSON-файле, на который ссылается профиль
проекта. В нём можно описать архитектурные предпочтения, требования
совместимости, приоритеты качества и другие устойчивые ограничения проекта.
Файл не должен содержать промпты, названия провайдеров или моделей, учётные
данные, исполняемые инструкции и абсолютные локальные пути.

Пример `docs/project-principles.json`:

```json
{
  "schemaVersion": "agent-project-principles.v1",
  "principlesId": "checkout-project",
  "revision": 1,
  "entries": [
    {
      "id": "public-contracts",
      "category": "architecture",
      "statement": "Публичные контракты должны быть расширяемыми и версионироваться.",
      "rationale": "Существующие интеграции должны читать старые конверты."
    }
  ],
  "authority": {
    "principlesRole": "defaults-and-constraints",
    "sourceOfTruth": "frozen-plan-and-lock",
    "semanticReview": "independent-review"
  },
  "source": {
    "kind": "project-local",
    "path": "docs/project-principles.json"
  },
  "productionPromotionClaimed": false,
  "principlesDigest": "<sha256-объекта-без-principlesDigest>"
}
```

Проверьте файл без запуска модели или внешнего CLI:

```bash
agent-lifecycle project principles check \
  --file docs/project-principles.json \
  --project-root .
```

Добавьте ссылку и отпечаток в `.alk/project-profile.json`:

```json
{
  "principles": {
    "path": "docs/project-principles.json",
    "digest": "<sha256>",
    "sourceOfTruth": false
  }
}
```

В профиле хранятся только путь и отпечаток. ALK не копирует текст принципов в
пакет выполнения и не позволяет этой ссылке понизить уровень риска, область
записи, обязательные проверки или требования к подтверждениям зафиксированного
плана.

## Дельты плана

Дельта сравнивает две явно указанные версии. Она показывает добавленные,
удалённые и изменённые требования, пути записи, критерии приёмки,
подтверждения, бюджеты, риски и контрольные точки. Изменения только в
документации выделяются отдельно и сами по себе не требуют нового lock-файла
для реализации.

```bash
agent-lifecycle plan delta \
  --before path/to/plan-v1/plan.manifest.json \
  --after path/to/plan-v2/plan.manifest.json \
  --before-lock path/to/plan-v1/plan.lock.json \
  --after-lock path/to/plan-v2/plan.lock.json \
  --out work/plan-delta.json

agent-lifecycle plan delta-check \
  --delta work/plan-delta.json
```

Сравнение не изменяет исходные файлы. Оно блокируется при несовпадении
идентификатора пакета, неправильном порядке ревизий, расхождении снимка или
lock-файла. Если изменились полномочия реализации, в отчёте устанавливаются
`reviewRequired: true` и `newLockRequired: true`; сам отчёт ничего не создаёт и
не утверждает автоматически.

## Когда это применять

Используйте принципы для устойчивого контекста проекта, который иначе пришлось
бы повторять в каждой задаче. Используйте дельту, когда в долгом проекте
появилось новое требование, изменился разрешённый файл, ужесточился бюджет,
добавилась проверка или сменился владелец работы. После этого проверяющий видит
точные категории полномочий, которым нужно новое ревью до продолжения
реализации.

См. также [профиль рабочего процесса проекта](project-workflow-profile.md),
[непрерывность плана](plan-continuity.md) и [архитектуру системы](../architecture/system-architecture.md).
