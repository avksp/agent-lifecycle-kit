# Источник правды

Agent Lifecycle Kit различает рабочие представления и источник правды.
Рабочие представления помогают агенту читать состояние, но не заменяют
зафиксированные артефакты.

Локальные настройки проекта находятся в `.alk/project-profile.json` и
проверяются `src/agent_lifecycle/project/profile.py`. Они задают значения по
умолчанию; зафиксированный план и соответствующий lock-файл сохраняют высшие
полномочия.

История изменений в исходном дереве хранится только в `CHANGELOG.md`, а
опубликованные версии фиксируются неизменяемыми GitHub Releases. Каталог
`release/candidate/` содержит игнорируемый генерируемый инвентарь и
доказательства: они пересоздаются из текущего дерева и не являются источником
правды.

## Правило документации

Документация объясняет поведение, но не является доказательством выполнения.
Для заявлений о релизе, зрелости адаптера или завершении задачи нужны
структурированные артефакты и проверки.

## Правило доказательств

Финальное завершение опирается на план, критерии приёмки, отчёты выполнения,
проверку реализации, проверку завершения и финальное подтверждение. Если данных
не хватает, процесс останавливается и требует явного решения.

## Правило входящих задач

Внешние issue, тикеты и импортированные данные являются только черновым входом.
Они могут помочь подготовить спецификацию, но не разрешают выполнение, не
фиксируют план и не заменяют проверенные исходные артефакты ALK.
