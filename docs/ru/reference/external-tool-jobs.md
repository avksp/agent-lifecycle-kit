# Ограниченные задания внешних инструментов

Ограниченные задания внешних инструментов позволяют адаптеру выполнять
необязательную длительную локальную работу и возвращать метаданные артефактов,
связанные дайджестами. Они нужны, когда специализированный аудитор, анализатор
или рендерер не успевает завершиться внутри одной синхронной внешней проверки.

Эта возможность не является очередью задач, daemon, средой выполнения модели
или контроллером workflow. В ядре ALK нет клиента провайдера и сетевых вызовов.
Адаптер владеет исполняемым файлом, учётными данными и возможным сетевым
поведением; ALK применяет существующую границу процесса без оболочки и проверяет
полученное evidence.

Обычный workflow не создаёт состояние внешнего задания. Для одноразовых
проверок архитектуры и зависимостей, завершающихся в вызывающем процессе,
продолжайте использовать `quality external-check`.

## Контракт задания

`agent-external-job-request.v1` связывает одну попытку со следующими данными:

- `jobId`, положительный номер `attempt`, идентичность адаптера и операции;
- вид выполнения `PROCESS` или принадлежащий адаптеру `NETWORK`;
- дайджесты дескриптора, зафиксированного плана, lock-файла, ревизии исходников
  и снимка исходников;
- явные лимиты времени, попыток, вывода, артефактов, стоимости, токенов и
  отмены;
- необязательные идентификаторы родительского задания, попытки и дайджеста
  запроса.

Используйте конструктор контракта, чтобы `requestDigest` вычислялся по
каноническому телу запроса:

```python
from pathlib import Path

from agent_lifecycle.contracts import canonical_bytes
from agent_lifecycle.contracts.external_job_schemas import build_external_job_request

request = build_external_job_request(
    job_id="dependency-audit",
    attempt=1,
    adapter_id="project-tools",
    operation="dependency-report",
    execution_kind="PROCESS",
    descriptor_digest="1" * 64,
    plan_digest="2" * 64,
    plan_lock_digest="3" * 64,
    source_revision="accepted-source-revision",
    source_snapshot_digest="4" * 64,
    limits={
        "maxWallSeconds": 120,
        "maxAttempts": 2,
        "maxOutputBytes": 65536,
        "maxArtifactBytes": 1048576,
        "maxArtifacts": 8,
        "maxCostMicros": 0,
        "maxReportedTokens": 0,
        "cancelGraceSeconds": 3,
    },
)
Path("job-request.json").write_bytes(canonical_bytes(request) + b"\n")
```

В примере используются условные дайджесты. Реальный адаптер должен связать
принятые дескриптор, план, lock-файл и снимок исходников.

## Запуск, просмотр и отмена

Передавайте argv после `--`; ALK не превращает его в команду оболочки:

```bash
agent-lifecycle adapter external-job run \
  --request job-request.json \
  --out work/dependency-audit.json \
  -- python -c "print('bounded check')"

agent-lifecycle adapter external-job status \
  --request job-request.json \
  --out work/dependency-audit-status.json

agent-lifecycle adapter external-job cancel \
  --request job-request.json \
  --out work/dependency-audit-cancel.json
```

Команда `run` синхронна на границе CLI. Другой процесс может обратиться к той
же выполняющейся попытке через `status` или `cancel`. Отмена идемпотентна и
связана с дайджестом запроса. Отмена, замеченная до завершения процесса,
побеждает; более поздний запрос возвращает `NOT_REQUIRED` и не может переписать
терминальный результат.

Последовательность состояний: `QUEUED`, `RUNNING`, затем ровно одно из
`SUCCEEDED`, `FAILED`, `CANCELLED` или `EXPIRED`. `NO_FINAL_VERDICT`, неполный
вывод, ошибка очистки, живой или отсутствующий объявленный дочерний процесс,
запись после завершения, устаревшая линия происхождения и превышенный лимит не
могут быть evidence приёмки.

## Приватное состояние и восстановление

Локальный корень по умолчанию:

```text
.alk/external-jobs/<jobId>/attempt-<n>/
```

Каталоги попыток создаются только один раз и отклоняют симлинки, разделители,
точечные идентификаторы и выход за корень. На POSIX каталоги нормализуются до
`0700`, а файлы до `0600`, включая вложенные каталоги артефактов. Существующая
попытка неизменяема. После прерывания восстановление создаёт новую попытку и
новое пространство артефактов, но не продолжает и не заменяет прежнюю попытку.

`maxWallSeconds` ограничивает выполнение процесса. Очистка может завершиться
после срабатывания лимита, поэтому переносимое `wallMilliseconds` ограничено
бюджетом выполнения, а приватный process receipt сохраняет полное время вместе
с очисткой. Превышение остаётся явным блокером. Такое разделение позволяет
сохранить правдивое evidence `EXPIRED` или `CANCELLED`, не ослабляя очистку и не
объявляя ложный успех.

## Дочерние задания и очистка

Дочерний запрос должен указывать точные идентификаторы родительского задания,
попытки и дайджеста запроса. При завершении родителя ALK отправляет отмену всем
объявленным дочерним заданиям и ожидает в пределах ограниченного окна
`max(0.15, cancelGraceSeconds * 3)` секунд. Окно покрывает завершение, проверку и
возможную эскалацию. Отсутствующий или продолжающий работу дочерний процесс, ошибка
очистки или его запись после завершения блокируют успех родителя.

Граница процесса владеет всей группой процессов. Пути тайм-аута, отмены и
лимита вывода сохраняют evidence очистки и не возвращают успех, пока
объявленный процесс остаётся живым.

## Evidence артефактов

ALK передаёт дочернему процессу каталог `artifacts/` текущей попытки через
`ALK_EXTERNAL_JOB_ARTIFACT_DIR`; адаптер записывает файлы только в этот каталог. ALK сохраняет
переносимые записи с контролируемым локатором, типом данных, числом байтов и SHA-256.
Сырые байты артефакта, stdout, argv и локальные абсолютные пути не входят в переносимое lifecycle evidence.

Сбор ограничен количеством и суммарным размером. Стабильное чтение отклоняет
файл, изменившийся во время хэширования. Симлинки, специальные файлы, выход за
корень, слишком большой объём и записи после завершения приводят к безопасному
отказу. Повторная запись тех же байтов также меняет метаданные идентичности
файла и делает результат непригодным.

## Полномочия и квалификация

Запрос, статус, результат и представление задания сохраняют
`authorityClaimed: false` и `productionPromotionClaimed: false`. Успешное
задание не принимает задачу, не замораживает план, не разрешает инструменты и
не публикует релиз. Зафиксированный план может потребовать независимо
проверенное evidence задания как один из входов приёмки.

Поддержка адаптера должна быть квалифицирована сценариями успеха, реального
тайм-аута, поздней отмены, очистки группы процессов, отмены дочерних заданий при
завершении родителя, replay, устаревшей линии происхождения, лимитов вывода и
артефактов, записи после завершения и `NO_FINAL_VERDICT`. Одного дескриптора или
успешного happy path недостаточно для заявления поддержки.
