# Объяснение эффективной конфигурации

В релизе 1.87 появилась одна команда только для чтения, объясняющая
конфигурацию, которая будет управлять операцией ALK:

```bash
agent-lifecycle project profile explain \
  --profile .alk/project-profile.json \
  --preset feature-implementation \
  --manifest tasks/release-1-87/plan.manifest.json \
  --lock tasks/release-1-87/plan.lock.json \
  --descriptor adapters/claude/adapter.descriptor.json \
  --capability-manifest adapters/claude/capabilities.manifest.json
```

Команда читает явно переданные файлы внутри проекта и возвращает
`agent-effective-configuration-explanation.v1`. Она не запускает хост, не
вызывает модель и не изменяет профиль, план или lock-файл.

## Приоритет источников

Приоритет задаётся отдельно для каждого поля и сообщается в результате:

1. встроенные значения по умолчанию заполняют незаданное поле;
2. встроенный preset задаёт значение ниже явного профиля проекта;
3. явный профиль проекта заменяет preset для принадлежащих ему полей;
4. ограниченное значение команды заменяет только разрешённое поле профиля;
5. полномочия зафиксированного плана являются ограничением, а не общим
   источником по правилу «последний побеждает».

Результат содержит `winningSource`, `overriddenSources` и `planConstraint`.
Для риска план задаёт минимальный уровень. Более строгий риск из команды
принимается, а понижение возвращает `risk-tier-downgrade`. Обязательный Review
Mesh и нерасширяющая политика thread bridge не могут быть отключены профилем
или командой.

Capability адаптера не выбирает значение. После проверки линии происхождения
дескриптора и capability-manifest он только сообщает, является ли выбранное
поле `GUIDANCE_ONLY`, `OBSERVED`, `ENFORCED` или `UNAVAILABLE`.

## Безопасный отказ при нарушении происхождения

До вывода о применимости проверяется соответствие дескриптора и
capability-manifest. Отсутствующие, неверные или устаревшие подтверждения
возвращают `UNAVAILABLE` и `status: FAIL`, сохраняя выбранное значение для
диагностики. Они не могут повысить поле или ослабить ограничение плана.

Результат содержит дайджесты и стабильные коды блокеров, но не исходный вывод
хоста, промпты, рассуждения модели, учётные данные или локальные абсолютные
пути.

См. [подтверждение действий адаптера](adapter-action-evidence.md), [профиль
рабочего процесса проекта](project-workflow-profile.md) и [необязательный
контроль жизненного цикла адаптера](../adapters/lifecycle-control.md).
