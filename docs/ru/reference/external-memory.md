# Внешний контекст

Поддержка внешнего контекста позволяет оператору явно импортировать локальный
файл с заметками или памятью как дополнительную подсказку для поиска по прошлым
эпизодам. Файл может быть выгрузкой из MCP-инструмента, базы заметок, прошлого
рабочего каталога агента или другого локального источника, но ALK сам не
обращается к этому источнику.

## Безопасный импорт

```bash
agent-lifecycle context external-import \
  --source work/context/project-memory.md \
  --citation "одобренная оператором выгрузка памяти проекта" \
  --out work/context/project-memory.external-context.json
```

Команда создаёт `agent-external-context-import-receipt.v1`. В артефакте
сохраняются отпечаток источника, ссылка на источник, статус обезличивания и
ограниченная очищенная подсказка. Артефакт устанавливает
`sourceOfTruth: false`, `rawContentStored: false`, `modelCallsStarted: false`,
`networkCallsStarted: false` и `providerApiCallsStarted: false`.

## Поиск по эпизодам

```bash
agent-lifecycle context episode-retrieve \
  --project-root . \
  --artifact work/run/final-proof.json \
  --external-context work/context/project-memory.external-context.json \
  --query "регрессионное подтверждение" \
  --out work/context/episode-retrieval.json
```

Внешний контекст выводится в блоке `externalContextHints`. Он не смешивается с
результатами поиска по эпизодам и не закрывает требования по доказательствам,
проверке или финальному подтверждению.

## Границы

- Внешний контекст является дополнительным и используется только после явного
  импорта.
- ALK читает только локальные файлы; он не вызывает MCP-серверы, сервисы
  поиска по базе знаний, провайдеров или CLI хостов.
- Секретоподобные значения и абсолютные локальные пути обезличиваются до
  записи артефакта.
- Внешний контекст может помочь при планировании или проверке, но приёмку
  закрывают только артефакты жизненного цикла, проверки, результаты валидации
  и финальное подтверждение.
