# Выполнение через workflow

В релизе 2.0 `workflow` стал единственным владельцем жизненного цикла.
Управляемое выполнение является операцией workflow, связанной с замороженным
планом, исходной ревизией, пакетом задачи и текущей ревизией состояния.

## Текущий маршрут

Гейт `plan-verification` проверяет замороженный манифест, lock и lineage
пакетов до разрешения этого маршрута.

```text
agent-lifecycle workflow run \
  --state <run.state.json> \
  --manifest <plan.manifest.json> \
  --operation-id <id> \
  --expected-revision <n> \
  --source-revision <sha>
```

Workflow владеет авторизацией, попытками задач, бюджетами, свежестью
результата, review, rework, внешними действиями и исходами финального аудита.
Активные схемы: `agent-workflow-run-receipt.v1` и
`agent-workflow-next-action.v1`.

## Что изменилось в 2.0

Прежняя публичная поверхность контролируемого runner удалена. Исторические
схемы и записи runner принимает только явный read-only конвертер
`workflow migrate-runner-artifact`. Это не запасной маршрут выполнения и он не
может записывать состояние workflow.

Конвертер ограничен, приватен и не заменяет существующий файл. Он проверяет
схему, дайджест, размер и стабильность входа, выдаёт
`authorityClaimed: false` и `stateWritten: false`, не запускает host или модель.

## Граница адаптера

Адаптер может помочь host выполнить операцию, но не владеет состоянием жизненного
цикла. Подтверждение host является evidence операции workflow и не может само
себя повысить, обойти review или заменить замороженный план. Обычный workflow
не импортирует код совместимой миграции.

## Политика совместимости

Конвертер входит в каждую поставку 2.x. Старые артефакты остаются читаемыми
через него, а новые задачи должны использовать состояние и подтверждения
workflow. Любое удаление требует отдельного аудита совместимости и запрещено до
решения для версии 3.0.
