# Локальная статистика качества и расхода

Quality-cost learning — локальный рекомендательный цикл поверх явных
артефактов ALK. Он помогает выбирать самый быстрый достаточный путь жизненного
цикла для похожих будущих задач, сохраняя `quality floor`.

Он не вызывает API провайдеров, не отправляет телеметрию, не обучает модель, не
требует полей стоимости в USD и не строит provider/model leaderboards в ядре.

## Поток

```bash
agent-lifecycle metrics outcome-index \
  --artifact <task-result.json> \
  --artifact <completion-gate.json> \
  --out <outcome-index.json>

agent-lifecycle metrics quality-signals \
  --index <outcome-index.json> \
  --out <quality-cost-signals.json>

agent-lifecycle metrics learn-recommend \
  --signals <quality-cost-signals.json> \
  --task-shape small-fix \
  --current-mode strict \
  --out <recommendation.json> \
  --summary-out <recommendation-summary.json>
```

`agent-task-outcome-index.v1` группирует локальные артефакты по форме задачи,
режиму жизненного цикла, классу маршрута и профилю. `agent-quality-cost-signals.v1`
показывает долю успешных запусков, долю блокеров, повторы, циклы исправлений,
токены, время выполнения и вызовы инструментов. `agent-lifecycle-recommendation.v1`
остаётся рекомендательным с `autoApply: false`, уровнем уверенности, отпечатками
подтверждений, метаданными отката и
`qualityFloorPreserved: true`.

Низкая уверенность оставляет текущий или минимальный режим. Любое изменение
политики должно идти через явный путь предложения и применения.

Для повторяющихся независимых проверок используйте отдельный процесс
[оптимизации проверок по подтверждённым данным](audit-optimization.md). Он
сначала проверяет качество, затем учитывает ресурсы процесса и сравнивает
кандидатов на общем ограниченном наборе эталонных задач.

## Повторяемое сравнение

Команда `agent-lifecycle benchmark evaluate` нужна, когда изменение процесса
следует сравнить с фиксированной основой качества, а не только с накопленной
статистикой. Встроенный набор применяет детерминированные правила и показывает
ложные приёмки, повторы, время и группы токенов с обозначенной достоверностью.
Синтетический результат не становится промышленным подтверждением. Подробнее:
[оценка по эталонным задачам](reference-task-evaluation.md).

Для сравнения нескольких вариантов выполнения или сред сначала проверьте
внешние записи выполнения в разделе [проверка вариантов выполнения по
эталонным задачам](benchmark-qualification.md). Она требует подтверждений
качества и минимального покрытия задач и групп до сравнения ресурсов;
неполные данные дают `NO_RECOMMENDATION`.
