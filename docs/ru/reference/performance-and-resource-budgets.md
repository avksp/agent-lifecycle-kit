# Бюджеты производительности и ресурсов

Релиз 1.78 уменьшает стоимость повторных локальных команд ALK и сохраняет
границы безопасности, совместимости и доказательств жизненного цикла. Числа,
которые собирает измерительный контур, описывают конкретное окружение и не
являются универсальной гарантией скорости.

## Что измеряет релиз 1.78

Привязанный к ревизии базовый отчёт сохраняет ревизию исходников, состояние
дерева, платформу, реализацию Python, число процессоров, прогрев, количество
измерений, ограниченный вывод и счётчики операций. По умолчанию проверяются
команда `version`, сканирование нейтральности области `tracked-release` и
расчёт канонического отпечатка.

Кроме времени выполнения проверяются свойства, которые важнее одной цифры:

- результат Ed25519 совпадает с векторами RFC 8032, принятыми квитанциями и
  строгой обработкой повреждённых входов;
- полное сканирование истории Git использует ограниченные пакетные потоки и
  сохраняет принятую инвентаризацию объектов и представление байтов;
- сопоставление правил запрета сохраняет идентификаторы правил, находки,
  порядок, дубликаты и поведение регулярных выражений;
- идентичность рабочего дерева использует потоковое чтение с ограничением,
  проверки устойчивости и оба снимка: до и после запуска;
- очистка процессов, ограничения вывода, тайм-ауты и граница `shell=False`
  остаются без ослабления;
- команда `version` не импортирует запуск внешнего хоста, управление
  процессами и сканирование нейтральности до выбора группы команды.

## Жёсткие проверки и справочные измерения

Жёсткие проверки определяют, можно ли принять доказательство. Время, память и
платформенные счётчики являются сравнительной информацией, если только план
явно не сделал их критерием приёмки. Неполное, устаревшее, смешанное по
окружениям или неограниченное измерение нельзя превратить в успешный результат
лучшим числом.

Единственный числовой критерий производительности в контракте приёмки 1.78 —
сравнение Ed25519 в одном чередуемом запуске: медианы получения открытого
ключа, подписи и проверки должны быть не более 20% от зафиксированной
аффинной реализации. Это сравнение не является заявлением о постоянном времени
выполнения или защите от побочных каналов.

## Ограничения ресурсов

Типизированные пределы выполнения определены в
`src/agent_lifecycle/contracts/performance_limits.py`. Политика релиза в
`policy/performance-budgets.json` может выбрать меньшее значение, но не большее.

| Область | Предел | Смысл |
| --- | ---: | --- |
| Процессы Git при полном сканировании | 4 по политике; оптимизированный маршрут использует 2 | Число процессов не растёт вместе с числом объектов. |
| Объекты Git | 1 000 000 | При достижении предела инвентаризация завершается отказом. |
| Инвентаризация Git | 128 МиБ | Вывод `rev-list` читается потоково. |
| Один объект Git | 16 МиБ | Слишком большой объект даёт неполное подтверждение, а не тихий пропуск. |
| Раскрытые данные Git | 4 ГиБ | Общий объём раскрытия ограничен. |
| Обрамление пакетного протокола | 128 МиБ | Обрамление ограничено отдельно от данных объектов. |
| Полное сканирование по времени | 600 секунд | Это срок проверки, а не разрешение вернуть частичное доказательство. |
| Неотслеживаемые файлы | 100 000 файлов / 4 ГиБ | Идентичность дерева не принимает неограниченный ввод. |
| Блок хеширования | 256 КиБ | Обычные файлы хешируются с ограниченной памятью. |
| Правила запрета | 1 024 правила / 4 КиБ каждое / 1 МиБ всего | Входы полномочий и политики проверяются вместе. |
| Простые строковые правила | 64 | Для большего принятого набора используется дифференциальный сопоставитель. |
| Снимки группы процессов Linux | 4 в секунду | Дорогой обход таблицы процессов выполняется с отдельной частотой. |
| Подтверждения за запуск | 96 МиБ | Объём доказательств не растёт без предела. |

При нарушении лимита, протокола, проверки устойчивого чтения или очистки ALK
возвращает структурированное неполное подтверждение или блокировку. Он не
исключает проблемный ввод, чтобы представить оставшиеся данные как полное
доказательство.

## Границы безопасной оптимизации

Допустимы изменения, сохраняющие наблюдаемые контракты: арифметика Ed25519 в
расширенных координатах с теми же векторами, долгоживущие ограниченные пакетные
процессы Git, дифференциальное сопоставление строк, потоковое хеширование
неотслеживаемых файлов, более редкий обход группы процессов Linux и ленивые
импорты после выбора команды.

По-прежнему запрещены кэширование подписей, профилей и результатов сканирования;
удаление одного из снимков дерева; пропуск проверок устойчивого чтения;
принятие обрезанных или слишком больших ответов Git; повышение лимитов вывода
и тайм-аутов; `shell=True`; ослабление проверки Ed25519; отключение редакции
секретов; превращение времени выполнения в полномочие над планом или релизом.

## Статусы, которые видит оператор

- `PASS`: объявленные смысловые проверки и ограничения ресурсов пройдены;
- `NO_RECOMMENDATION`: сопоставимых данных о производительности недостаточно;
  это не заявление о скорости и не замена обязательным доказательствам;
- `INCOMPLETE`: сканер или измерение достигли лимита, обнаружили ошибку
  протокола, неустойчивый ввод или другое условие отказа по умолчанию;
- `BLOCKED`: не выполнено обязательное условие безопасности, владения,
  совместимости или очистки процессов.

## Повторение проверок

Запускайте команды из рабочего дерева проекта с Python 3.11-3.14:

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src \
python3 tools/performance/run_performance_baseline.py \
  --policy policy/performance-budgets.json \
  --repository-root . \
  --output work/performance-baseline.json

PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src \
python3 tools/release/validate_performance_evidence.py \
  --policy policy/performance-budgets.json \
  --input work/performance-baseline.json \
  --evidence work/performance-validation.json
```

Обычная релизная проверка использует `tracked-release`. `full-repository`
включайте только тогда, когда план явно требует проверки исторических объектов
Git. Его ограничения и неполный результат являются частью контракта
доказательств.

В отчёте производительности хранятся отпечатки, счётчики и ограниченные сводки.
В него нельзя записывать запросы, вывод хоста, секреты окружения, исходное
содержимое объектов Git или приватные локальные пути. См. [проверку
нейтральности](neutrality.md), [ресурсы и безопасность в рабочих
запусках](../guides/production-resource-security.md) и [архитектуру
системы](../architecture/system-architecture.md).
