# Agent Lifecycle Kit

Agent Lifecycle Kit (ALK) координирует работу кодового агента до проверяемого
завершения. Он связывает ожидаемый результат, проверенный план, границы
выполнения, подтверждения и решение о приёмке, пока внешний агент меняет проект.

Проект работает поверх разных CLI: Codex, Claude Code, Qwen Code, Goose,
OpenInterpreter, Pi, Grok Build и других. Ядро не зависит от конкретного
провайдера или модели; команды, настройки окружения и работа с секретами
выносятся в адаптеры или локальные профили хоста.

Задача проекта — обеспечить проверяемое завершение работы внешнего агента с
соразмерным уровнем контроля. ALK добавляет только необходимые проверки и
подтверждения, а основное время остаётся на исследование, реализацию и проверку
продукта.

**Лицензия:** Apache-2.0 · **Версия:** 2.4.0 · Python 3.11-3.14

Английская документация: [английская версия на GitHub](https://github.com/avksp/agent-lifecycle-kit/blob/main/README.md).

## Быстрый старт

Начните с подробного руководства [установка ALK и первый запуск](guides/install-and-first-run.md).

Описание переносимого пакета навыков находится в разделе [переносимый пакет Agent Plugins](reference/agent-plugins.md), проверка установленного пакета - в разделе [проверка Agent Plugins в клиентах](reference/agent-plugin-qualification.md), а необязательный контроль жизненного цикла адаптера - в [отдельном справочнике](adapters/lifecycle-control.md). Сейчас комплектные адаптеры публикуют `GUIDANCE_ONLY` и `NO_RECOMMENDATION`, а управляемый запуск сохраняет статус `WRAPPER_ONLY`.

В нём есть варианты для macOS, Linux и Windows, установка из [PyPI](https://pypi.org/project/agent-lifecycle-kit/) командой `python -m pip install agent-lifecycle-kit==2.4.0` и разбор ошибок команды `agent-lifecycle version`.

Для быстрого старта выполните:

```bash
git clone https://github.com/avksp/agent-lifecycle-kit.git
cd agent-lifecycle-kit
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
agent-lifecycle version
agent-lifecycle diagnose --no-install-plans
```

Выберите `<adapter-id>` в [матрице поддержки адаптеров](adapters/support-matrix.md)
и передайте задачу из файла:

```bash
agent-lifecycle start --adapter <adapter-id> --file task.md
```

## Что даёт ALK
- Процесс ориентирован на результат: план, выполнение, проверка и подтверждение
  завершения.
- Один подход для разных CLI: особенности конкретного инструмента остаются в
  адаптерах, а новые адаптеры можно добавлять без изменения схем жизненного
  цикла.
- Маленькие и локальные модели получают компактный контекст, понятный следующий
  шаг и повторяемые проверки.
- Единая стратегия объединяет риск, класс модели, размер пакета, проверку и
  ограничения ресурсов без снижения обязательного качества.
- Учёт расхода показывает токены, время, ресурсы и структурированные записи о выполнении без чувствительных данных; денежная стоимость необязательна и используется только если её сообщает платный хост.
- Настройки рабочего процесса проекта: ALK находит и проверяет локальные значения по умолчанию, которые не попадают в Git, и предлагает встроенные профили для распространённых маршрутов; источником полномочий остаётся зафиксированный план. CI также контролирует ацикличный граф модулей и пакетов, направление слоёв и ограничения размера исходников; осмотр адаптера выбирается через ограниченный литеральный профиль и завершается безопасным отказом без выполнения кода адаптера при неподдержанной возможности.
- Прогресс и управляемые сессии работают без вызова модели: команда `start`
  принимает текст, файл задачи, зафиксированный запрос или сохранённую сессию,
  не заявляя прямой запуск внешнего инструмента.

## Области возможностей
### Планирование и выполнение
- Спецификация и план проверяются до начала изменений в коде.
- Работа делится на пакеты с владельцем, разрешёнными файлами и критериями
  приёмки.
- Выполнение, блокировки, ограниченные повторные попытки и итоговое подтверждение
  фиксируются в структурированных артефактах; при доработке ALK сохраняет прошлый
  результат и требует актуальный снимок Git до приёмки новой попытки.
- Есть сформированные шаблоны задач, которые покрывают исправление ошибок, путь
  от идеи до PR, проверку PR, исправление конфликтов слияния и подготовку
  релиза.

### Качество и подтверждение
- Аудит реализации сравнивает результат с зафиксированным планом и
  подтверждениями приёмки.
- Дополнительный профиль расследования для задач по ошибкам и
  регрессиям фиксирует воспроизведение до правки, устойчивый
  отпечаток ошибки, журнал гипотез, минимальную правку и регрессионную проверку.
- Контроль целостности для рискованных финальных подтверждений хранит
  устойчивые выводы проверки, отпечатки причины, влияние правки и цепочку хэшей.
- Перепроверка и проверка правил запуска включаются по требованию плана. Если
  задача должна записать результат во внешнюю систему, план может потребовать
  отдельное подтверждение такой записи до приёмки.
- Дополнительная проверка несколькими моделями ИИ поддерживает любые доступные связки адаптеров и моделей; Codex, Claude Code и OpenCode/GLM — только примеры. Review Mesh готовит задания, объединяет выводы и проверяет кворум; модели запускает оператор или обёртка хоста. Набор эталонных задач строит стратифицированную выборку и проверяет или сравнивает варианты выполнения только при достаточном объёме данных; при его нехватке возвращается `NO_RECOMMENDATION`.

### Маршрутизация и расход
- Компактные пакеты для маленьких моделей, краткие профили контекста, снимки
  цели и локальная статистика качества помогают выбрать самый лёгкий безопасный
  режим.
- Оптимизация проверок по подтверждённым данным объединяет локальные сигналы
  качества, времени, токенов и ресурсов; профиль предлагается после проверки
  на эталонных задачах, каждое изменение требует явного подтверждения.
- Измерения по этапам фиксируют токены, длительность и счётчики ресурсов без
  обязательной денежной оценки.
- Экспорт использования показывает сессии, токены, ресурсы, отпечатки
  подтверждений и необязательный `cost_usd`, если его сообщает хост.

### Безопасность и ограничения среды
- Проверка нейтральности выпуска связывает индекс Git и текущую ревизию, а игнорируемые локальные подтверждения читает только по явному ограниченному политикой флагу. Запрещающие правила хоста не дают локальным путям, секретам, корням доверия и ключам подписи попасть в переносимые артефакты.
- Файлы окружения для хостов требуют явного `--host-env-allow`; артефакты сохраняют только обезличенные метаданные, а общий запуск CLI по дескриптору блокируется до создания процесса.
- Импорт, диагностика и экспорт использования маскируют локальные пути и типовые признаки секретов до проверки.
- Артефакты песочницы отделяют ограничения файловой системы, сети, процессов и окружения от разрешённых путей записи в Git.
- Проверки безопасности релиза отклоняют утечки локальных путей, учётных данных и неподтверждённые заявления об адаптерах или промышленной готовности.

### Адаптеры и импорт
- Адаптеры отделяют команды, настройки и ограничения конкретного CLI от схем
  жизненного цикла.
- Новый CLI подключается через дескриптор, правила запуска, границу окружения и
  отдельные подтверждения проверки; ядро при этом не меняется.
- Отображение прогресса показывает состояние жизненного цикла без изменения
  зрелости адаптера и без разбора телеметрии хоста в ядре.
- Проверки возможностей адаптера строят ограниченные планы пробных запусков и
  сравнивают реальные подтверждения без автоматического изменения статуса.
- Импорт внешних процессов, форматов агентов и тикетов используется только как
  черновой вход для последующей проверки.
- Поиск по прошлым эпизодам работает с краткими резюме подтверждений и сессий,
  сохраняя признак проверенной или непроверенной цепочки.

### Операции
- Артефакты восстановления запуска покрывают снимок попытки, восстановление,
  отказ от попытки, выбранную попытку, закрепление исполнителя и сигнал
  активности.
- Диагностика готовности, лента событий, управляемый шаг, наблюдение за прогрессом и счётчик изменений не меняют состояние и не запускают модель.

## Уровень поддержки адаптеров
Уровень поддержки показывает, какая часть интеграции ALK проверена для
конкретного внешнего инструмента. В него входят заявленная версия CLI,
проекция команд, граница окружения, проверка реального хоста, калибровка
ресурсов и принятые подтверждения жизненного цикла. Это характеристика
проверенного диапазона интеграции, а не оценка модели или внешнего продукта.

К принятым артефактам жизненного цикла относятся проверенный план и lock-файл,
подтверждения переходов состояния и задач, сводки проверок и доказательств,
независимые аудиты плана и реализации, а также итоговое доказательство. Для
запуска внешнего хоста добавляются подтверждения расхода, ресурсов и
ограничений среды для точной связки адаптера и версии.

`EXPERIMENTAL` означает, что адаптер описан в исходниках и проходит повторяемые
локальные проверки. `VERIFIED` добавляет ограниченную проверку реального хоста,
калибровку расхода, принятое обезличенное резюме подтверждений и финальное
подтверждение жизненного цикла для указанного диапазона. Точные версии,
проверенные связки провайдера и модели, а также состав подтверждений указаны
на страницах адаптеров и в матрице поддержки. Матрица охватывает Codex, Claude
Code, Cursor, Gemini CLI, Goose, Grok Build, Hermes, Kimi Code, OpenCode,
OpenInterpreter, Pi и Qwen Code.

Подробнее: [Установка адаптеров](adapters/install.md), [матрица уровня поддержки адаптеров](adapters/support-matrix.md) и [поддержка управляемых сессий](adapters/managed-session-support.md).

## Границы проекта
- Ядро не зависит от конкретного провайдера. Команды хоста и выбор модели
  живут в адаптерах или локальных профилях.
- Новые CLI подключаются через адаптеры: дескриптор, правила запуска, граница
  окружения и подтверждения проверки. Схемы жизненного цикла при этом остаются
  стабильными.
- Маленькие модели получают компактные пакеты, детерминированные проверки и
  явные следующие действия.
- Большие модели проходят те же обязательные проверки качества; более сильное
  рассуждение не заменяет подтверждающие артефакты.
- Публичные заявления релиза опираются только на отслеживаемые файлы и
  обезличенные резюме подтверждений.
- Git write-scope ограничивает пути репозитория; артефакты песочницы описывают
  ограничения среды запуска и могут оставаться `UNKNOWN` до отдельной проверки.
- Импорт внешних форматов и найденные прошлые эпизоды помогают с контекстом, но
  не заменяют проверенные исходные артефакты ALK.
- Дополнительная перепроверка, несколько моделей ИИ и правила запуска добавляют подтверждения
  только при запросе задачи или плана; это не режим одновременного запуска моделей.
