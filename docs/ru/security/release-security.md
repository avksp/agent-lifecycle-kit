# Безопасность релиза

Релизные заявления должны подтверждаться отслеживаемыми файлами, проверками и
обезличенными резюме доказательств. Локальные рабочие артефакты, секреты и
абсолютные пути не должны попадать в репозиторий.

## Контроль безопасности релиза 1.75

В релизе 1.75 границы исходного дерева и публикации связаны одной цепочкой
проверок:

- подписанное подтверждение нейтральности связывает утверждения с операцией и
  основным артефактом;
- аргументы ревизий Git проверяются до формирования отчёта только для чтения;
- входные данные из репозитория с симлинками отклоняются, а локальный запуск
  фиксирует идентичность разрешённого исполняемого файла;
- общая редакция удаляет распространённые отдельные токены до сохранения
  подтверждений;
- ограничения JSON, права закрытых файлов и строгий разбор Ed25519 работают с
  отказом при нарушении условия;
- зафиксированный пакет плана связывается с lock-файлом до аудита и запуска;
- CI и публикация используют неизменяемые ссылки на Actions, защищённые теги
  релиза и уже настроенный PyPI Trusted Publisher.

Происхождение дистрибутивов 1.75.0 проверяется после публикации защищённым
workflow. Для колеса и исходного архива 1.74.0 уже подтверждено успешное
использование Trusted Publishing.

## Что проверять

- `git diff --check`;
- отсутствие секретов и локальных путей в отслеживаемых текстовых файлах;
- если обвязка реального хоста использует локальный файл окружения, должен быть
  явный `--host-env-allow` и подтверждение от `validate_host_env_hygiene.py`;
- `agent-lifecycle contract check`;
- `agent-lifecycle diagnose --no-install-plans`;
- актуальность заметок релиза и changelog.

## Что нельзя заявлять

Заявление публичного одобрения каталога, промышленной готовности или уровня
поддержки `VERIFIED` опирается на проверенные артефакты и принятое финальное
подтверждение.
