# Матрица поддержки адаптеров

Матрица фиксирует заявление исходного дерева об уровне поддержки адаптеров.
Уровень описывает проверенный объём интеграции ALK для конкретного хоста:
версию CLI, проекцию команд, границу окружения, проверку реального хоста,
калибровку ресурсов и подтверждения жизненного цикла. Это характеристика
диапазона интеграции, а не оценка модели или внешнего продукта. Матрица не
заменяет локальные проверки: перед использованием нужно запускать `diagnose`,
`adapter validate` и `adapter inspect`.

Различия между подключением ALK внутри внешнего инструмента и запуском
контроллера из терминала проекта описаны в разделе [использование ALK с
адаптером](usage-modes.md).

К принятым артефактам жизненного цикла относятся проверенный план и lock-файл,
подтверждения состояния и задач, сводки проверок и доказательств, независимые
аудиты плана и реализации и итоговое доказательство. Для запуска через
проверенный профиль добавляются подтверждения расхода, ресурсов и ограничений среды.

Поддержка управляемых сессий отделена от уровня поддержки адаптера. Текущие встроенные
адаптеры объявляют `managedLaunch.status: WRAPPER_ONLY`: подтверждение
жизненного цикла связывается с управляемыми командами или обёртками. Для
принятого запуска зафиксированной задачи используется проверенный локальный
профиль. Подробнее: [управляемые сессии адаптеров](managed-session-support.md).

Пользователь может отдельно включить проверенный локальный маршрут через
профиль в `.alk/host-launch/`. Он использует зафиксированные привязки и профиль
риска и возвращает локальное подтверждение.
Подробнее: [локальный запуск внешней команды](../reference/local-host-launch.md).

Для всех двенадцати встроенных адаптеров предусмотрены локальные профили с
точной привязкой к версии. Они позволяют воспроизводимо создать профиль и
проверить версию. Профили используют совпадающее локальное подтверждение и
сохраняют `WRAPPER_ONLY`. Подробнее:
[запуск зафиксированной задачи через проверенный
профиль](../reference/qualified-host-launch.md).

Для запуска только планирования действует отдельный статус. Все
двенадцать адаптеров имеют результат для точной версии. Codex `0.147.0`, Claude
Code `2.1.226`, Gemini CLI `0.46.0` и Goose `1.45.0` являются статическими
кандидатами; остальные восемь профилей имеют статус `UNSUPPORTED`. Матрица
планирования показывает состояние профиля каждого адаптера и команды подготовки
квалификации. Подробнее: [запуск адаптера только для
планирования](../reference/planning-only-launch.md).

Локальный учёт токенов имеет отдельный статус. Claude Code, Codex, Gemini CLI,
Kimi Code, OpenCode и Qwen Code объявляют
`usageNormalization.status: FIXTURE_ONLY`: их ограниченные
нормализаторы проверены на тестовых образцах, а квалификация S1/S2 использует
подтверждения хоста. Для остальных встроенных дескрипторов действует статус
`UNSUPPORTED` этого контракта. Уровень поддержки Qwen Code остаётся `VERIFIED`,
а нормализатор следует собственной декларации. Подробнее:
[локальный учёт токенов хоста](../reference/host-local-token-accounting.md).

## Захват событий

Дескрипторы и манифесты возможностей объявляют `adapter-event-stream` через
переносимую схему `agent-adapter-event.v1`. Офлайн-проверки требуют
`agent-adapter-event-stream-receipt.v1`, который связывает поток событий с
отпечатком дескриптора. Это отдельная проверка качества артефактов; уровень
поддержки опирается на полный набор подтверждений из матрицы.

Захват событий имеет границу `adapter-owned`. Оператор или адаптер настраивает
native hook или маршрут через обёртку, а ядро ALK проверяет переносимые
артефакты и состояние жизненного цикла. На странице каждого адаптера указаны
native hook, маршрут через обёртку, маршрут артефакта и владелец настройки.
Подробности описаны в
[матрице захвата событий адаптеров](event-capture-matrix.md).

Подтверждения проверки возможностей — это детектор расхождений для реальной
совместимости. План строится из `agent-adapter-capability-manifest.v1` и задаёт
детерминированный набор операций для проверки. Проверка подтверждений сравнивает артефакты реального хоста с
планом и падает при пропущенной запланированной операции, синтетическом
повторе для операции, требующей реального запуска, или обходе оболочки
host-protocol.

Подтверждения песочницы используют только `agent-sandbox-receipt.v1`. Частичные
ограничения дерева процессов и границы прокси для учётных данных записываются в
деталях артефакта; значения секретов и полные пути к приватным env-файлам
недопустимы.
