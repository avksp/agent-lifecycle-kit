# Матрица поддержки адаптеров

Матрица фиксирует заявление исходного дерева о поддержке адаптеров. Она не
заменяет локальные проверки: перед использованием нужно запускать `diagnose`,
`adapter validate` и `adapter inspect`.

Поддержка управляемых сессий отделена от зрелости адаптера. Текущие встроенные
адаптеры объявляют `managedLaunch.status: WRAPPER_ONLY`: ALK может связать
работу с подтверждением жизненного цикла через управляемые команды или
обёртки, но не заявляет безопасный прямой argv-запуск CLI. Подробнее:
[управляемые сессии адаптеров](managed-session-support.md).
Любой общий запрос запуска через дескриптор блокируется кодом
`adapter-generic-launch-disabled` до создания процесса хоста; статус
дескриптора не может обойти эту границу.

Локальный учёт токенов имеет отдельный статус. Gemini CLI, Kimi Code и Qwen
Code объявляют `usageNormalization.status: FIXTURE_ONLY`: их ограниченные
нормализаторы проверены на тестовых образцах, но результаты ещё не подходят для
гейтов S1/S2. Для остальных встроенных дескрипторов контракт не объявлен, что
равнозначно `UNSUPPORTED`. Зрелость Qwen Code остаётся `VERIFIED`, но сама по
себе не подтверждает новый нормализатор. Подробнее:
[локальный учёт токенов хоста](../reference/host-local-token-accounting.md).

публичное одобрение каталога, npm-публикацию или готовность других версий.

## Захват событий

Дескрипторы и манифесты возможностей объявляют `adapter-event-stream` через
переносимую схему `agent-adapter-event.v1`. Офлайн-проверки требуют
`agent-adapter-event-stream-receipt.v1`, который связывает поток событий с
отпечатком дескриптора. Это проверка качества артефактов, а не повышение
зрелости адаптера.

Автоматическая установка: нет. Захват событий имеет границу `adapter-owned`.
Ядро ALK не устанавливает hook хоста, не пишет конфигурацию хоста и не
разбирает сырую телеметрию. Состояние hook, маршрут через обёртку, маршрут
артефакта и статус автоматической установки описаны в
[матрице захвата событий адаптеров](event-capture-matrix.md).

Подтверждения проверки возможностей — это детектор расхождений для реальной
совместимости. План строится из `agent-adapter-capability-manifest.v1`, не
запускает реальные вызовы, не меняет зрелость и не заявляет промышленную
готовность. Проверка подтверждений сравнивает артефакты реального хоста с
планом и падает при пропущенной запланированной операции, синтетическом
повторе для операции, требующей реального запуска, или обходе оболочки
host-protocol.

Подтверждения песочницы используют только `agent-sandbox-receipt.v1`. Частичные
ограничения дерева процессов и границы прокси для учётных данных записываются в
деталях артефакта; значения секретов и полные пути к приватным env-файлам
недопустимы.
