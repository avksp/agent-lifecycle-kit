# Использование ALK с адаптером

ALK можно использовать внутри поддерживаемого внешнего инструмента или как
отдельную команду в терминале проекта. Эти способы можно сочетать, но они дают
разные гарантии.

## Работа внутри внешнего инструмента

Подключаемый модуль или навык объясняет кодовому агенту порядок работы ALK.
После установки откройте целевой проект во внешнем инструменте и дайте явное
указание, например:

```text
Используй навык agent-workflow-orchestrator для этой задачи.
Сохраняй план ALK, состояние, результаты проверок, подтверждения и итоговое доказательство в проекте.
Задача: <опиши задачу или укажи Markdown-файл>
```

Выбор модели, вызов инструментов, подтверждение действий и запуск процесса
остаются ответственностью внешнего инструмента. Установка или упоминание навыка
сама по себе не доказывает прохождение жизненного цикла. Для такого заявления
нужны переходы состояния ALK и принятые подтверждения.

## Запуск из терминала проекта

Ту же задачу можно передать в ALK без запуска внешнего инструмента:

```bash
agent-lifecycle start --adapter <adapter-id> --file task.md
agent-lifecycle start --adapter <adapter-id> --text "Проверь устройство кеша"
```

Замените `<adapter-id>` идентификатором из таблицы со ссылками ниже. Обычный
текст или Markdown создаёт черновое подтверждение, требующее проверки. Команда
не вызывает модель и не запускает внешний инструмент, если оператор отдельно
не указал квалифицированный маршрут `--launch`.

Этот способ удобен для сценариев автоматизации, воспроизводимых подтверждений,
подготовки непрерывной интеграции и инструментов без готового подключаемого
модуля. Внешний агент также может сам вызывать эту команду. Доказательством
жизненного цикла будут её подтверждения, а не факт установки модуля.

## Способы подключения встроенных адаптеров

| Адаптер | Идентификатор | Поставляемый способ работы внутри инструмента |
| --- | --- | --- |
| [Codex](codex.md) | `codex` | Установить модуль Codex, перезапустить сессию и запросить `agent-workflow-orchestrator`. |
| [Claude Code](claude.md) | `claude` | Установить модуль Claude, выполнить `/reload-plugins` и запросить `agent-workflow-orchestrator`. |
| [Cursor](cursor.md) | `cursor` | Подключить каталог модуля Cursor, перезагрузить Cursor и запросить `agent-workflow-orchestrator`. |
| [OpenCode](opencode.md) | `opencode` | Скопировать общие навыки и JS-проекцию в настроенные каталоги OpenCode, затем запросить навык. |
| [Hermes](hermes.md) | `hermes` | Установить навык из отмеченной версии и выполнить `/agent-lifecycle-kit:agent-workflow-orchestrator`. |
| [Gemini CLI](gemini-cli.md) | `gemini-cli` | Инструмент умеет находить навыки, но адаптер не меняет его каталог; подключите общие навыки из отмеченной версии вручную или используйте терминал. |
| [Kimi Code](kimi-code.md) | `kimi-code` | Инструмент позволяет выбрать каталог навыков, но адаптер их не устанавливает; подключите общие навыки вручную или используйте терминал. |
| [Pi](pi.md) | `pi` | Подключите навык из отмеченной версии через штатную настройку AGENTS/Agent Skills или используйте терминал. |
| [Goose](goose.md) | `goose` | Готовый модуль ALK для работы внутри инструмента не поставляется; используйте терминал или собственную проверенную обвязку. |
| [Grok Build](grok-build.md) | `grok-build` | Готовый модуль ALK для работы внутри инструмента не поставляется; используйте терминал или собственную проверенную обвязку. |
| [OpenInterpreter](openinterpreter.md) | `openinterpreter` | Готовый модуль ALK для работы внутри инструмента не поставляется; используйте терминал или собственную проверенную обвязку. |
| [Qwen Code](qwen-code.md) | `qwen-code` | Встроенная проекция не заявляет готовый способ установки ALK внутрь внешнего инструмента; используйте терминал или отдельно проверенную настройку. |

Перед изменением файлов внешнего инструмента выполните
`agent-lifecycle adapter install-plan --descriptor
adapters/<идентификатор>/adapter.descriptor.json`. Команда только показывает
план установки и ничего не устанавливает.

## Отличия двух способов

| Свойство | Внутри внешнего инструмента | Команда `agent-lifecycle` |
| --- | --- | --- |
| Запуск модели | Возможен по правилам внешнего инструмента. | Нет, пока явно не выбран квалифицированный маршрут `--launch`. |
| Выбор модели и поставщика | Выполняет внешний инструмент или оператор. | ALK не выбирает их, а хранит только нейтральный маршрут и принятые подтверждения внешнего инструмента. |
| Чтение задачи | Агент читает запрос или указанный файл. | ALK читает `--text` или `--file` и создаёт ограниченное подтверждение. |
| Доказательство полного цикла | Установка модуля или навыка его не даёт. | Требуются принятые переходы состояния, проверки, аудиты и подтверждения. |
| Основной сценарий | Интерактивная работа в инструменте, который загружает навыки ALK. | Автоматизация, воспроизводимость и работа с инструментами без модуля. |

## Прямой запуск внешнего процесса

Параметр `--launch` включает третий, более узкий маршрут. Он не равнозначен
работе ALK внутри внешнего инструмента. Для запуска планирования требуется
состояние `PLANNING_ONLY_QUALIFIED`; сейчас все встроенные адаптеры безопасно
отказывают для этого состояния. Для запуска реализации нужны полный
зафиксированный запрос, профиль риска, локальный профиль с точной версией и
соответствующее подтверждение предварительной проверки.

В качестве принятого доказательства запуска можно использовать только
поддержку, указанную в разделе [квалифицированный запуск зафиксированной
задачи](../reference/qualified-host-launch.md). Наличие описания профиля или
успешная проверка `--version` сами по себе недостаточны.

См. также [установка адаптеров](install.md), [матрица поддержки
адаптеров](support-matrix.md) и [запуск адаптера только для
планирования](../reference/planning-only-launch.md).
