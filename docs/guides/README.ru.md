# Agent Lifecycle Kit

Agent Lifecycle Kit помогает вести работу агента от постановки задачи до
финального доказательства результата. Набор не привязан к конкретной среде:
ядро описывает жизненный цикл, а адаптеры переводят его в команды конкретных
CLI и плагинов.

Главная цель проекта: доводить задачу до конца с максимально возможным
качеством для выбранной модели и при этом видеть, сколько ресурсов уходит на
саму работу и сколько на контроль жизненного цикла.

## Что Входит

- Проверяемая спецификация и замороженный план до начала реализации.
- Пакеты задач для исполнителей с владельцем, границами записи и критериями
  приемки.
- Квитанции выполнения, блокировки, повторные попытки и финальное
  доказательство.
- Контракты адаптеров без привязки ядра к конкретному поставщику.
- Компактный контекст и короткие снимки цели для небольших локальных моделей.
- Учет расхода по категориям: реализация, проверка продукта, контроль цикла и
  координация.
- Детерминированные отчеты о расходе по явным артефактам жизненного цикла.
- Советы по режиму жизненного цикла на основе накопленных отчетов о расходе.
- Явные предложения по настройке правил жизненного цикла с откатом.
- Диагностика готовности без записи файлов и без запуска живых модельных
  вызовов по умолчанию.

## Быстрый Старт

Из исходного дерева:

```bash
python -m pip install -e .
agent-lifecycle version
agent-lifecycle diagnose --no-install-plans
agent-lifecycle adapter validate --descriptor adapters/codex/adapter.descriptor.json
```

Короткий пошаговый пример: [quickstart.ru.md](quickstart.ru.md).
Полный список документов: [docs/README.md](../README.md).

## Обычный Цикл

1. Уточнить задачу и ограничения.
2. Подготовить спецификацию и план.
3. Проверить план и заморозить его.
4. Выполнить ограниченные пакеты задач.
5. Проверить реализацию по плану.
6. Завершить только после совпадения приемки, доказательств и остаточных
   рисков.

Основные группы команд:

- `agent-lifecycle specification`: проверки спецификации.
- `agent-lifecycle plan`: проверки плана, замки, снимки и передача ревьюеру.
- `agent-lifecycle workflow`: квитанции задач и финальное доказательство.
- `agent-lifecycle audit`: проверка плана и реализации.
- `agent-lifecycle metrics`: отчеты о расходе и их проверка.
- `agent-lifecycle policy`: предложения по настройке правил жизненного цикла.
- `agent-lifecycle diagnostics`: редактированные пакеты доказательств.
- `agent-lifecycle diagnose`: готовность исходного дерева без записи и живых
  вызовов.
- `agent-lifecycle adapter`: проверка, осмотр, создание заготовки адаптера,
  события и сухой план установки.
- `agent-lifecycle model`, `context`, `goal`, `followup`, `worktree`,
  `runner`, `metrics`, `quality`, `report`, `evidence`, `import`, `contract`,
  `schema`: вспомогательные команды жизненного цикла.

Справочник команд: [CLI Reference](../reference/cli.md). Где находится
источник правды по каждому типу данных:
[Source Of Truth](../reference/source-of-truth.md).

## Зрелость Адаптеров

`EXPERIMENTAL` означает, что у адаптера есть исходная проекция и
детерминированные офлайн-проверки, но продвижение не заявлено. Для `VERIFIED`
нужны ограниченная живая совместимость с конкретной версией среды, успешные
калибровки расхода, принятое редактированное резюме доказательств и финальное
доказательство жизненного цикла.

| Среда | Текущее заявление |
| --- | --- |
| Codex | `VERIFIED` для Codex CLI 0.145.0. Одобрение публичного Plugins Directory не заявлено. |
| Claude Code | `VERIFIED` для Claude Code 2.1.220. Одобрение официального каталога не заявлено. |
| OpenCode | `VERIFIED` для OpenCode CLI 1.18.9. Публикация в npm не заявлена. |
| Hermes | `VERIFIED` для Hermes Agent v0.19.0. Одобрение публичного каталога не заявлено. |
| Qwen Code | `VERIFIED` для Qwen Code 0.21.0 на проверенной связке GLM 5.2. Одобрение публичного пакета не заявлено. |
| Cursor | `EXPERIMENTAL`; безопасный осмотр прошел локально, но живые квитанции неполные. |
| Gemini CLI | `EXPERIMENTAL`; локальная живая проверка заблокирована текущим уровнем Gemini Code Assist. |
| Kimi Code | `EXPERIMENTAL`; для живого доказательства нужен настроенный поставщик и псевдоним модели. |

Подробности установки: [Adapter Install](../adapters/install.md). Полная
матрица: [Adapter Support Matrix](../adapters/support-matrix.md).

## Карта Контрактов

Публичная поверхность жизненного цикла привязана к схемам. Эти имена стабильны
и используются в документах, тестах и квитанциях:

- Завершение: `completionCheck`,
  `agent-completion-check-receipt.v1`.
- Непрерывность цели: `agent-goal-record.v1`,
  `agent-objective-snapshot.v1`.
- Управляемое выполнение: `agent-runner-state.v1`,
  `agent-runner-snapshot.v1`.
- Последующие работы: `agent-follow-up-register.v1`,
  `agent-follow-up-summary.v1`.
- Изоляция рабочего дерева: `agent-worktree-isolation-policy.v1`,
  `agent-worktree-attempt-receipt.v1`.
- События адаптера: `agent-adapter-event-stream-receipt.v1`,
  `agent-adapter-event-capture-validation.v1`.
- Проверочные вердикты: `agent-review-verdict.v1`,
  `agent-review-routing-summary.v1`.
- Дополнительные проверки качества: `agent-optional-quality-pack.v1`,
  `agent-behavior-check-run.v1`.
- Диагностика и статус: `agent-diagnostic-bundle.v1`,
  `agent-readonly-status-view.v1`.
- Предложения по правилам цикла: `agent-lifecycle-policy-proposal.v1`,
  `agent-lifecycle-policy-tune-result.v1`.

Полный список: [Public Contracts](../reference/public-contracts.md).

## Границы Проекта

- Ядро остается нейтральным к поставщикам. Команды конкретной среды и выбор
  модели хранятся в адаптерах или локальных профилях.
- Маленькие модели получают компактные пакеты, детерминированные проверки и
  короткий список следующих действий.
- Большие модели используют те же ворота качества; лучшие рассуждения не
  заменяют доказательства.
- Сухой запуск, заготовка, осмотр или синтетический прогон не повышают
  зрелость адаптера.
- Публичные заявления релиза опираются только на отслеживаемые файлы и
  редактированные резюме доказательств.
