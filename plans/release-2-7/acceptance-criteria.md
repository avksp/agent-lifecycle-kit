# Acceptance criteria

| ID | Requirement | Evidence | Deterministic acceptance |
| --- | --- | --- | --- |
| `AC27-ROUNDS` | `R27-ROUNDS` | `EV27-ROUNDS` | `manifest_contract` accepts only a non-boolean integer `maxPlanReviewRounds` from 1 through 10. A reviewer participates only through a schema-valid `agent-review-verdict.v1` bound to a complete, blocking-eligible `agent-external-job-result.v1` from `SUCCEEDED`; every other terminal state or `NO_FINAL_VERDICT` is resource use without participation. Round evaluation joins all synthesis buckets to immutable dispositions: an open `MEDIUM`, `HIGH`, `CRITICAL` or `BLOCKER` finding blocks unless its disposition is `REJECTED`. Exhaustion returns only REPLAN_REQUIRED, SPLIT_REQUIRED, OPERATOR_DECISION or BLOCKED and cannot produce ACCEPTED. |
| `AC27-SEVERITY` | `R27-SEVERITY` | `EV27-SEVERITY` | One canonical blocking-severity set contains exactly `BLOCKER`, `CRITICAL`, `HIGH` and `MEDIUM`. The existing independent-review, structured-verdict, task-review, implementation-audit report, final implementation-audit, finalization, specification-completion and plan-package review gates all consume that set and reject a PASS/ACCEPTED/READY outcome carrying an open finding at every listed severity. |
| `AC27-CHECKS` | `R27-CHECKS` | `EV27-CHECKS` | Raw reproduction text never becomes argv; only an approved frozen check profile can execute, and every result is source/plan/check bound. |
| `AC27-DISPOSITION` | `R27-DISPOSITION` | `EV27-DISPOSITION` | Every imported finding has exactly one immutable terminal disposition and evidence; unavailable/no-verdict is distinct from rejected or confirmed. Replay is idempotent, a conflicting terminal update fails closed, and reviewer agreement alone cannot create or change a disposition. |
| `AC27-PROVENANCE` | `R27-PROVENANCE` | `EV27-PROVENANCE` | Statistical evidence declares source class, derivation, stable sample identity, source revision/lineage and independence; duplicate identities, stale lineage and implementation/holdout samples with an undisclosed shared producer fail closed. |
| `AC27-ADEQUACY` | `R27-ADEQUACY` | `EV27-ADEQUACY` | Effective independent count includes only unique, current-lineage samples that satisfy the declared independence rule. A 2% zero-error claim using rule-of-three requires at least 150 such samples and a 1% claim requires 300; 149 and 299 fail with stable adequacy blockers. |
| `AC27-METRICS` | `R27-METRICS` | `EV27-METRICS` | Metrics distinguish confirmed, rejected, no-verdict and remediation use and never recommend a lower quality floor or automatic apply. A tracked portable fixture reproduces the Release 2.6 baseline (`29,195,208` audit tokens; `9,278,567 ms` audit wall; `12,228,901 ms` audit compute; process/implementation/remediation tokens `UNAVAILABLE`) and cannot emit a reduction percentage from that single distinct sample. |
| `AC27-DISTINCT-COMPARISON` | `R27-DISTINCT-COMPARISON` | `EV27-DISTINCT-COMPARISON` | Across the current input and every comparison, each of `releaseId`, `sourceRevision`, `sourceLineageDigest` and label-independent content digest is pairwise unique. The content digest is `canonical_digest(input - {releaseId, inputDigest})`. Reusing the current artifact, aliasing it through another path, changing only `releaseId`, retaining source lineage while changing other metrics, or repeating any comparison fails with `audit-efficiency-comparison-duplicate-identity` before a measured reduction or inflated `sampleCount` can be emitted; two genuinely distinct complete releases still produce the existing comparison result. |
| `AC27-PUBLICATION` | `R27-PUBLICATION` | `EV27-PUBLICATION` | Documentation, schemas, package and plugins consistently identify `2.7.0`. |
